## Choices and decision

1. **Use request-scoped evidence references.** Project generic, bounded candidate passages under stable request-local IDs that carry actual source identity/path, allowed kind and text with surrounding context. For unambiguous executable statements and limitations, expose the already derived span and operation using Python AST/tokenize and the installed Pygments lexer with the existing conservative witness rules. Bound candidate volume, retain negations and adjacent branches, and expose omissions. Documentation can use native source lines grouped into bounded passages. Let the model select evidence and author the claim and report structure. Resolve IDs to provenance, kind, exact lines and symbol server-side; independently revalidate against the original body and re-open the actual file. Retain the SDK agent, ToolExecutor permissions, timeout and single-write semantics. This changes the internal report interface and requires separate source/design authority for product adoption. Difficulty is useful coverage without flooding the context or omitting critical surrounding text. A handle for a real warning must never certify the truth of an arbitrary claim.
2. **Constrain the wire schema.** A request-scoped schema that models separate action/final envelopes, code versus documentation and admissible references can remove invalid field combinations. The installed Ollama client types accept schema-valued format; the present OpenJarvis engine discards it. A narrow approved SDK transport change with wire-level proof would be necessary on this path. Preserve security and instrumentation and check actual deployed grammar support. Ordinary integer bounds alone cannot express the cross-field span relation. This option chiefly improves mechanical reliability and cannot correct the provider assertion. Lower priority than choice 1.
3. **Keep the candidate frozen and measure semantic capability separately.** A diagnostic comparison on immutable evidence can distinguish source-reading errors from bookkeeping load without a new product candidate. A different model would be a separate comparison requiring new availability and authority. There is no evidence that a larger model alone would solve the interface problem.
