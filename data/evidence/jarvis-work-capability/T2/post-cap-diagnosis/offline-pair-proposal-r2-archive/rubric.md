# Independent semantic rubric (freeze before model use)

Reviewer receives this document and the four shuffled P packets only. Each packet contains the natural question, submitted report headings/claims and source bodies with proposed citations normalized to common locations. Score each independently before the controller unlocks the assignment. Write P ID, source URL and range, explicit supported/contradicted/insufficient ruling with a short source quotation for each substantive assertion (including titles/headings), then case-level coverage and polarity. Missing proposal or no recoverable claims fails coverage. No answer revision or repair. Treat omission as omission, never as a true contrary statement.

For each assertion check (1) correct project/source identity, (2) excerpt supports the full assertion including negation, scope and conditions, (3) neighboring lines do not reverse its meaning, (4) relevant to the requested subject. Distinguish behavior supported by a local call from performed runtime behavior, and lack of implementation at one branch from system-wide absence. A real source URL alone earns no credit. Extra claims count and can fail the case.

E02 coverage requires at least three distinct relevant sources, an evidenced desktop behavior or architecture fact, active agent/provider wiring or task execution, and a genuine observation about the open-source base or a properly scoped distinction supported by available sources. If an integration is claimed, require source proof of that specific link. Explicitly inspect each provider assertion against branch behavior. The held-out case requires true material from all three source files on secure write, sensitive-path handling and signature verification, including at least one accurately distinguished error or fallback branch. Do not award credit for mentioning a class or filename without explaining behavior.

Record claim counts by label, whether every claim is supported and relevant, case coverage, branch polarity and project attribution separately. A semantic pass requires at least three grounded source identities, coverage and no contradicted/unsupported substantive claims. A mechanical pass is separately assessed by the controller through the frozen renderer, scoped path and strict output contract. Only a handle result passing both gates on both cases, with improved joint outcome on the originally failing subject and no held-out regression, merits considering an interface implementation. Both passing both variants is non-discriminating. If grounding stays wrong after mechanical gains, stop. No outcome substitutes for E02 acceptance.

The packet's report object groups each verbatim heading with its own source and claims in submission order. Inspect the title and every heading, including contradictory or unsupported framing with otherwise true facts. For malformed/no-report states, grade any recoverable text and record missing coverage explicitly. No proposal is not a zero-error success.
