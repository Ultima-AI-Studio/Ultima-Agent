**SPEC REVISE · QUALITY REVISE.** The SDK route is viable in principle. The proposed HTML exclusion changes the supported input contract, and the design does not yet define enforceable failure handling and bounded, independently reproducible native transport receipts. Review of design only. No candidate or runtime qualification.

## Findings for one bounded author revision

1. **P1 · SPEC · preserve projected documentation and define availability.** Design lines 27–32 and 61 exclude extracted HTML and propose only a negative test. The frozen evidence protocol line 7 assigns HTML lines to extracted visible text. Browser channel lines 145–172 already keeps decoded body and projected text separately, excluding script/style nodes from the latter. Research lines 323–338 and 367–381 support projected documentation and restrict raw code coordinates separately. Three distinct otherwise admissible official HTML pages now deterministically fail before the author sees a catalogue. This is a functional regression even though the four fixed sources happen to be raw MD/TS/TS/PY. In the retained controlled receipt they are all text/plain, untruncated, with identical body/text, 7,236 / 3,252 / 4,643 / 13,559 UTF-8 bytes and 205 / 90 / 110 / 367 lines. That is structural eligibility only. Preserve safe documented projections with explicit coordinate domain, extractor version, original decoded and projected hashes, scanner policy on both domains, and deterministic independent reconstruction. Treat non-identical/unmappable code as unavailable. Define a usable source as having a card with full citation that fits at least one legal final rendered page, not merely valid URL/body and suffix. A 4-line documentation anchor made entirely of individually oversized lines, or a source with every line excluded, supplies no such card. Require three mutually distinct usable identities before POST and three distinct actually issued sources with usable cards before offering write. Test positive HTML documents and mixed code/docs plus unsafe markup, changed projection and three empty/uncitable sources with zero POST. No handpicked winners.
2. **P1 · QUALITY · give the SDK-created instances a fail-closed dispatch handoff.** Design lines 15–16, 19, 40–44. Jarvis accepts names, then sdk.py:468–489 calls cli/ask.py:308–343 to instantiate its own zero-argument registered class on the caller. A separately preconstructed instance cannot be validated as the executing tool. START in tools/_stubs.py:378–392 has only tool, parsed arguments and agent, not an instance or react call ID. Current agent_server.py:450–459 checks caller thread and captured binding identity. That check is sound for the subscription but does not establish which object will claim authority. In core/events.py:153–163 callback exceptions are swallowed and executor proceeds. Specify construction-time enrollment of the exact SDK-built tool in the request ledger, a capability-limited inspector instead of inherited full caps (work_tools.py:220–235), and atomic worker claim of its enrolled identity + pending request/seq/name/args. Pin the dispatch and adapter IDs in END metadata, verify bounded result content, seal in the callback before returning on mismatch, and require the worker to observe the seal before touching files. Distinguish the caller binding check from the worker object check. Test second same-binding object with identical args, skipped/failed observer, wrong/duplicate START, stale worker, failed END and timeout before/after intent. A failed observer must not become an authorization path. Preserve existing SDK timeout and loop-guard failures without promoting their synthetic observations (native_react.py:326–355). No event bus or global changes required.
3. **P1 · QUALITY · pin the actual transport object and replayable authority inputs.** Design lines 40–48 use an actual secure POST input hash, a sanitized message serialization to reproduce it, and an N3 derivation including a random nonce. NativeResearchLeaf (agent_server.py:245–285) sends an Ollama request containing rendered message dicts, projected format, options, model and flags. A sanitized messages-only hash cannot independently identify that full entity. Guards inspect message content and output, not the serialized native options (guardrails.py:167–217). Specify distinct digests for exact native entity bytes actually sent, ordered complete post-guard message history, strict schema and sampler projection. Hash the built request at the send boundary; compare system/query and each assistant/USER observation against the expected phase-specific secure chain. Persist nonce and precise handle input encoding, view ID derivation, scan/coordinate policy version, serialized argument/response limits and corresponding raw-vs-secured action checks in a sealed replay format. Failing or secret-bearing messages need outcome/counter-only or digest-only retention. A claimed issued witness whose safe replay evidence cannot be retained must not reach the writer. Test changes solely to options/schema/system/older assistant, guard rewriting current or earlier observations, metadata loss, changed nonce or view, and partial POST without promotion. Keep staged third read eligible for sampler only, with actual handle promotion after successful raw and secured validation and before SDK dispatch.
4. **P2 · QUALITY · separate byte, context and time limits and test actual first-attempt charging.** Design lines 56–61. Six reads × 3,072 = 18,432 observation bytes, with at most eight POST starts, 32,768 bytes of messages+schema per turn and up to 262,144 such bytes across eight turns. History is replayed with outer JSON escaping, so 18,432 is not a cumulative input-traffic bound. The reported context estimator in engine/_base.py:101–119 uses characters/4 plus message overhead; prompt_eval_count can count only new tokens on cache hit. Retain native overflow rejection/truncate=false/shift=false; counts or this estimator alone cannot certify full context. Specify which exact encoding and schema layer is counted, bound the full HTTP entity and native response bytes (including errors/partial bodies) before buffering. Current agent_server.py:282–297 uses buffered post() before validation. Define the pre-send reservation, partial-body outcome and no retry in tests using a scripted inference transport at the real request boundary. Account for all prewrite possibilities including inspect selected on writer-capable turn, SDK guard rejection, and deadline immediately after metadata. Keep 260 s as an admission deadline with unresolved in-flight effects, not a guaranteed cancellation time. Do not assume all maximal histories fit. A positive minimal three-read chain must actually fit the full SDK system, initial query, prior actions, observations, writer arguments and ACK.
5. **P2 · QUALITY · resolve conflicting format instructions and make positive tests diagnostic.** Design lines 16, 40, 57, 60–61 preserve real SDK system instructions and append phase rules. The installed default native_react.py:24–34 explicitly requires Thought/Action/Action Input or Final Answer text while the proposed native grammar and full validator require a closed JSON envelope. The installed parser accepts JSON (lines 72–114, 173–187). State exactly which recognized format clause v3 supersedes in the actual model-visible system while preserving SDK tools/security/history, and pin real template/overrides. Assert no mutually exclusive output instructions. Scripted envelopes alone cannot demonstrate model comprehension. For the positive SDK test, have the test double select from the observed catalogue/actual returned cards at runtime (e.g. permuted synthetic source fixtures with independently known neutral text), derive arguments from dynamically issued handles and compare against independent bytes and locations. Add a permutation and negative counterfactual that would fail with canned IDs, hardcoded source order, synthesized observations or prewritten winning claims. Keep separate semantic review of original material.
