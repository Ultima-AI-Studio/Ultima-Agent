## 1. What changes at the product boundary

After successful SDK search and GET, give the current author a compact catalogue. Let it choose windows of the already fetched sources within one NativeReAct conversation. The next generation receives each real inspector observation alongside the original question. Once sufficient distinct sources have actually been shown, the author can submit one report. This makes “never inspected”, “inspected but uncited” and “cited but unsupported” distinguishable. No server-authored facts, model score or predetermined source order enters the task.

## 2. Exactly what can be inspected and cited

| Boundary | v3 rule |
|---|---|
| Trusted input | Up to five already accepted GETs. For a source truncated at GET, >256 KiB decoded UTF-8, >1,024 lines, invalid hash, or unsupported coordinate map, mark unavailable with reason. Identity/hash or GET-ledger mismatch aborts request. First version supports only identity text/body and LF/CRLF; explicitly mark extracted HTML and other projections unsupported, never label projected lines as raw. Unknown suffix can be listed but cannot supply a witness. Fail before generation with fewer than three usable URL/body identities. |
| Security before any tool output | Inside trusted preparation use the same configured SDK scanners on the complete original text and on individual numbered lines. In BLOCK mode a full-text finding blocks the source. Otherwise remove entire affected lines even under WARN. Require sequential whole-text redact output to equal the concatenated individually redacted lines with original separators, and scan the redacted projection for residual findings. If mapping, scanner behavior or separators disagree, deny the whole source. Exclude dirty lines from all text, operation labels and anchors, keep only line number/reason. Scan catalogue labels, action descriptions and complete serialized observation before exposure. Security exclusions cannot be reversed by another page. Frozen original data remain available only to trusted verification. |
| Catalogue ≤4,096 UTF-8 bytes | Per source give S label, safe final host/path identity, suffix, line count, available/omitted reason and neutral navigation landmarks. Landmarks are up to eight evenly spaced eligible anchor coordinates and literal operation names in source order (for docs, coordinates only). Drop whole landmarks from the end round-robin until fit. If mandatory identities cannot fit or safely identify provenance, fail. No claim, ranking, preferred sources or citation handles. Catalogue is data. |
| ToolSpec | Closed object {source_id: S1…S5, start_line: integer 1…1024}. One call reads at most 24 consecutive original line positions starting there, never beyond EOF. Return compact JSON {v,source_id,view_id,start,end,total_lines,lines,cards,omissions,next_start}. lines are [original_line,text], cards are [ref,kind,operation,anchor_first,anchor_last,citation_first,citation_last]. Missing lines explicitly tagged security or size; next_start advances past the examined range. No URL, file path, raw read, arbitrary search string, network, queue or memory facility. |
| Size and selection | At most 3,072 serialized UTF-8 bytes including metadata per observation, eight cards, six successful or attempted reads per request, 18,432 bytes total. First reserve bounded omission-run metadata, then add full lines in order, skipping oversized individual lines; never split a line. Add cards only from actually fitting lines, stopping at card or byte cap. Remove whole trailing entries as required to fit, record size omissions or count of omitted cards, fail if metadata alone exceeds cap. Duplicate same start/source or invalid requests fail, no replay. Different starts may overlap, all calls count. |
| Evidence construction | In trusted preparation reuse _anchors, _python_witnesses, _js_tokens, _fact_evidence and complete-statement limits from source9. Validate anchors on original source, filter through the safe lines. Per window choose in ascending (first,last,kind,symbol) order, no relevance selection. Use up to eight contiguous actually returned lines around the ≤8-line anchor as in v2, stopping at every gap. A model may discuss local conditions/alternatives visible in that citation and submit separate atomic claims with other issued witnesses. Nearby activity alone does not prove a control dependency. |

## 3. Issuance, one write and reopening

| State under request ledger lock | Admission and terminal behavior |
|---|---|
| READY → EXPECT(tool,args_digest,seq) | Each generation validates its exact prior assistant/observation chain against the ledger. Closed ReAct JSON union contains one action with object arguments or one nonempty final_answer. Start with inspect/refuse. Internally require three distinct issued URL and body identities for writer eligibility. At the read limit permit only eligible write or final. Prewrite final means refusal/failure. No arbitrary final-answer success. |
| EXPECT → START → STAGED | Caller-thread subscription checks bound object identity, SDK tool name, canonical args digest and single expected sequence; allocate dispatch UUID at START. Insist on one pending dispatch. Worker atomically claims matching (request,seq,tool,args_digest), records adapter UUID, hashes, complete safe observation and prospective handles before returning. END must succeed once, match worker record by linked UUID, exact observation bytes, caller and request. Never infer success from reply text or ask_full's stripped tool_results. Timeout, absent START/END, out-of-order or late receipt seals first failure, bars further admission. |
| STAGED → ISSUED | At the next leaf, after guard input scanning and immediately before transport, compare the exact SDK USER observation including prefix and every previously issued observation with the expected ordered secure bytes. Any change, redaction, clipping or missing history aborts before POST. Stage prospective handles only; promote atomically only after this exact POST returns a valid complete raw envelope, the full secured envelope also validates and matches the raw action/args or final. Thus the current action may cite what its own input actually contained. For deciding if the **current sampler** may offer write, count the pending confirmed observation provisionally as well as issued reads; the worker requires promotion before consuming authority. Failure never issues new usable handles. |
| ISSUED → FROZEN → WRITE_INTENT | On secured writer action freeze ordered issued set at that generation; no more reads. Consume the one report reservation on actual SDK writer dispatch, check captured identities, every reference and distinctness, render completely, call checked_path then existing nested WorkWriteTool → real SDK FileWriteTool(allowed_dirs=[root]). Exactly one consumed intent, no public file tool offered. No direct bound invocation may bypass confirmed SDK START on v3. Invalid inputs give zero file writes. |
| CONFIRMED → ACK → CLOSED | Require one successful writer END, exact report/file adapter IDs and completed effect, verified binding/root, file bytes and independent render before final-only ACK. Service reopens again and external acceptance independently opens and hashes the real file. Missing END, unknown/partial writes, timeouts with unresolved writer, readback or ACK failure after an effect → needs_attention and retain all evidence. Pre-effect confirmed rejection → failed. Close on observed deadline/disconnect/cutoff, freeze first outcome and disable late worker admissions; record late effects separately. Never retry or mask first failure. |

Use a short opaque v3 handle per card (“N3.” plus first 16 hex of SHA-256 over canonical version, random request nonce, binding triple, source ID/URL/body hash/GET adapter ID, inspect dispatch/adapter IDs, seq and anchor/citation coordinates, kind, operation and visible-text hashes). Reject collisions. The worker can construct prospective handles before END. IDs have no authority without exact membership in the ordered, issued snapshot. Persist snapshot records with complete safe lines/cards, omissions, timestamps, input order, actual secure POST input hash, valid raw/secured output hashes, commit generation, and GET/source/projection links. Record generation identity independently from model input. Retain the exact sanitized message serialization used to reproduce the input hash in restricted receipts; check credentials/PII exclusion before persistence. Never save a secret-bearing rejected message. No text parsed from an untrusted source can create a ledger entry.

Writer arguments retain path/title/sections[3..5] with unique source_id/heading/facts[1..6], each fact {claim,evidence_id}. Constant schema uses string bounds and v3 handle syntax with no reference enums. Keep v2 text limits, reject extra keys, verify request/path, exact symbol and witness, kind, citation under original GET, URL/body uniqueness, authorized visible lines, and ≥3 independent sources server-side. Resolve v3 rendering against that card's immutable actually issued view, never v2 _source_view or the union of windows. Receipt protocol_version=3 binds submitted and resolved payload, ordered bindings, safe view records, report/file IDs and byte SHA-256. External replay recomputes from sealed GETs, actual confirmed read/event/wire records and submitted facts, compares exact lines/UUIDs/hash chain to the separately sealed packet manifest, then re-renders and reopens. Mechanical linkage and syntax do not decide factual entailment. Independent review checks every claim against its cited passage, local conditions and alternatives, attribution to the two distinct projects and original task coverage.

Unknown version, missing original immutable data, unknown/foreign/stale/unissued handle, hash drift, cross-window span or v2 ID under v3 fails closed. No automatic migration.
