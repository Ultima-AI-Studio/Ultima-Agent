# 阶段一开发任务验收对照清单（Stage1 Acceptance Checklist）

- **版本**：v2.2 · 2026-10-21
- **性质**：执行级验收文档（覆盖阶段一全部开发任务：目标/结果/对照过程总表；CodeX 照单执行 + 主脑审计共用）
- **权威口径**：acceptance-spec v1.3（DoD 四层 + §6 执行红线 I1-I3/B1 + §7 结果反推 + §8 自核闭环）· version-plan v1.0（v0.1→v1.0 里程碑）· product-plan v2.3 §8（成功信号）· codex-task-queue-spec v1.3（队列/状态机/展示口径/报告语言）· ops-selfcheck v1.6（零弹窗绝对纪律）
- **用法**：CodeX 每完成一个 L1 单元 → 按「L1 单元对照」列到对应任务卡核对「写什么/验收（逐项）/证据」→ 填「证据」列 → 主脑审计打勾「结果/结论」→ 版本组尾触发冻结门 → v1.0 全绿打 tag

## 0. 对照流程（怎么验）

| 层级 | 对照动作 | 产出 |
|---|---|---|
| 单元级 | CodeX 执行 → **对照本表验收 Gate 逐项自核** → 任一不过先自修（≤2 次）→ 全绿才提交回执三件套（完成语+落地文件清单+验收证据，I1）→ 主脑独立审计（反推改动清单核对，不沿用自述） | 单元结论 PASS / FAIL / BLOCKED |
| 版本级 | 该版本全部单元 PASS → 版本 DoD 总验收 → 关联文档同步（docs/README 登记）→ 冻结 tag | 版本报告归档 docs/reports/ |
| 项目级 | 五版本全过 + §8 四信号全绿 + DoD 项目级 PASS | tag `stage1-v1.0-frozen` |

红线：失败回执必须结构化（I3：失败命令/错误原文/根因/下一步）；证据不明确一律 fail-closed 判 BLOCKED 留主脑（B1），绝不猜测性 PASS；每任务重试 ≤2 次，超限转 BLOCKED。

**主脑审计附加检查（MUST，Top 教训固化）**：
- **无悬空终态检查（N5）**：审计时核查任务库——不存在停留在失败/冻结却无后续事件的悬空记录；每条任务必须走到终态（已完成/已取消），未达终态 → 报警并转冻结留主脑处置（不删记录、保证闭环）。
- **报告语言中文化（N6）**：审计报告/状态汇报一律中文直白表达——失败就是失败、冻结就是冻结、通过就是通过；禁止 FAILED/BLOCKED/PASS 等工程英文状态词堆砌（技术名首次可加中文括号备注一次）；违反即打回重写。状态中文映射见 queue-spec §10。

**提交前自核闭环（CodeX 义务）**：验收标准随任务卡一起下发（goal + acceptance 逐项）；CodeX 执行完成后必须先对照 acceptance 逐项自核，自核未全绿不得提交回执——先自修（≤2 次）再交。自核不豁免主脑独立审计（防自证清白，acceptance-spec §3），但自核到位可把打回率压到最低。
