## 3. 任务明细（三段式）

### T1 · 上下文预算自洽（E-02）

**文件**：基线 §16.2（n_ctx 行）、§16.4（新增）
**写什么**：
1. 复算冲突：`4000 + max(512) = 4512 > 4096`，给出算式与出处行号。
2. **A 案**：`input_budget(profile) = n_ctx − max_output(profile) − template_overhead`；量化表**固定 5 列**：`profile / max_output / template_overhead / input_budget / 是否合法(≤n_ctx)`；各行数值由公式算出。
3. **B 案**：抬 `n_ctx` 的代价（内存增量、首 token 延迟区间，一律标"估算"）＋ 回读门（§16.4 回读对账需同步改哪一行）；**`n_ctx` 目标值写 `D-04` 占位，本 T 不得出现任何具体数值**。
4. 两案各写一段，**结论写 `D-04` 占位**；`n_ctx` 字面值不得改动。

**验收（Gate T1）**：
1. 冲突算式存在且数字与 L748/L773 一致（脚本取数比对）。
2. 量化表恰好 5 列且行数＝主脑 profile 数（decision/dialog 至少 2 行）。
3. `D-04` 占位出现 1 处；`n_ctx = 4096` 原文仍在（diff 可证未改）。

**禁止**：直接改 `n_ctx` 数值；只写"建议调大"不给公式。

### T2 · 全卷满承诺（E-04）

**文件**：基线 §17.2.3
**写什么**：
1. 指出不可实现点："排队需要持久介质；审计追加同理"，并引 L904 原句。
2. **A 案块**：预留 `emergency_journal`，写"容量与位置见 D-05 附表"，给触发与回灌流程（不含具体容量）。
3. **B 案块**：给出**固定替换文本**（逐字）：`采集任务排队等待，不保证不丢；审计写入失败记事件并继续服务`。
4. 事件名统一 `journal_unavailable`（仅 1 个）。

**验收（Gate T2）**：
1. 原句"不丢、不失败"在 §17.2.3 内出现次数＝0（脚本计数）。
2. A/B 两案各有段落标题，**每块首行必须带机器可见状态字段 `status=selected` 或 `status=rejected`**，且全文恰有一处 `selected`（脚本计数）；`IF D-05=` 标记 2 处。
3. `journal_unavailable` 全文出现 1 次。
4. 未出现任何具体容量数字（正则扫 `\d+\s?(MB|GB)` 在新增段落内计数＝0）。

**禁止**：保留原承诺句只加注释；自定应急区容量。

### T3 · 容量与卸载口径（E-05）

**写什么**：三项（单库硬顶、库内删除、卸载门）各加一行 `[obsolete]` 标记，指向唯一现行章节（分别 → §17.2.3、§17.2.3、§16.1）；保留历史数值但标"作废"。
