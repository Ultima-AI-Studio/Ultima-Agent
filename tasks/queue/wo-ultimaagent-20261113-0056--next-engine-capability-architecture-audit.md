## 3. 任务明细（三段式）

### T1 · 反推漏项（应有而无）

**文件**：`docs/reports/evidence/audit-0056/t1_chain_gaps.md`

**写什么**：
1. 以六条运行时链路为线索，**从零反推**"跑通该链路最少需要哪些能力"，**不允许**以盘点 27 项为出发点（那是造成漏项的原因）：
   - L1 启动与自检：进程拓扑、端口占用、依赖就绪、崩溃自恢复、单实例
   - L2 唤醒与听写：KWS 常驻、VAD 尾音、ASR 接续、打断（barge-in）、失败降级
   - L3 理解与决策：意图分级、路由、上下文装配、拒答与澄清、外脑不可用降级
   - L4 执行与工具：工具注册与调用、权限闸、超时与取消、结果回执、幂等
   - L5 记忆与温度：写入、检索、习惯抽取、分层迁移、容量与降级、隐私授权
   - L6 治理与更新：策略校验、审计留痕、灰度和回滚、安装与卸载零残留
2. 与树 113 节点、盘点 27 项逐一比对，只保留**断点型缺失**：缺该项则该链路某一步接不上。
3. 每条格式固定：`链路 / 断点步骤 / 应有能力 / 现状（节点或章节在哪、写了什么）/ 依据（文档哪句隐含该需求）/ 严重度 / 一句话修法`。

**验收（Gate T1）**：六条链路各有反推表；断点型缺失每条都能指出"缺了以后哪一步接不上"；无"锦上添花"条目；与 48 条已知去重后编号 `G-01…`。

**禁止**：把"体验优化"写成缺失；把盘点已列项换句话重报；只给结论不给断点。

### T2 · 空壳与半成品节点

**文件**：`docs/reports/evidence/audit-0056/t2_hollow_nodes.md`

**写什么**：
1. 对树中 113 个节点逐个检查六要素：①输入 ②输出／产物 ③状态 ④参数或阈值 ⑤失败路径 ⑥验收口径或数据落点。
2. 缺 ≥3 项 → 空壳；缺 1–2 项 → 半成品；六要素齐全 → 有定义。
3. 输出表：`节点路径（父链用 → 连接）/ 六要素勾选 / 判定 / 缺什么 / 依据（详解页或基线对应节）`。
4. 汇总：有定义 N／半成品 N／空壳 N，并指出**空壳集中在哪几条链路**。

**验收（Gate T2）**：节点数与 `tree.json` 的 `node_count` 一致（113）；逐节点有判定，无"抽样"；空壳与半成品分别计数；每条缺项能指到具体文档位置。

**禁止**：抽查代替全量；把"有名字"当作"有定义"；把文案缺失与设计缺失混为一谈。

### T3 · 设计错误与硬约束冲突

**文件**：`docs/reports/evidence/audit-0056/t3_design_errors.md`

**写什么**：对照下列硬约束逐项检查设计是否写错，每条给出"设计原文 vs 约束要求"两处引用与后果：
1. **进程拓扑**：Console 与 `queue_engine` 同 pid；定时为 Console 内子模块、非独立常驻；禁守护/计划任务；壳不得 CreateProcess。
2. **端口与端点**：主脑 `mainbrain:11435`；8756 只读视图唯一读口；`11434` 不得作主脑后端。
3. **平台无关层**：Core／Voice／Memory／Middleware／Update 禁 Windows-only 依赖。
4. **磁盘分层**：热 500 MB／温 2 GB 定值；冷层无上限但路径可指定、禁公有云盘；卷 95% 停收新分片；分层迁移触发条件是否写明。
5. **权限与隐私**：外部主脑三闸（会话级授权一次／禁全文外发／本地库禁读）；沙箱双层（Job Object ＋ 写域白名单）是否都落到设计。
6. **拓扑健康**：单点（某能力只有一处实现且无降级）、职责重叠（两模块同称负责）、循环依赖、参数互斥（两个阈值/冷却互相矛盾）。

**验收（Gate T3）**：六类各查过并写明"查过且无问题"或"有问题+编号"；每条冲突双引用；编号 `E-01…`；后果写成"会怎样坏"而非"不规范"。

**禁止**：把 0055 已修的 F-002／F-003／F-004 重报；用"建议优化"代替"设计错"。

### T4 · 依赖与闭环（断链／孤儿／无主）

**文件**：`docs/reports/evidence/audit-0056/t4_contract_gaps.md`

**写什么**：
1. 建立模块清单（以树的三层与盘点 §1.1 的三类为准），对每一对"调用方→被调方"检查契约：接口名、入参出参、错误码、超时、幂等要求是否在两份文档中成对出现。
2. 输出三类问题：
   - **断链**：调用方声明了调用，但被调方无接口定义（或反之）。
   - **孤儿能力**：能力存在但无任何调用方（谁用它？答不出即为孤儿）。
   - **无主能力**：多模块都声称负责，或所有模块都未声明。
3. 失败与回滚：每条跨模块调用是否写明失败分支与回滚（尤其执行域失败、记忆写入失败、外部主脑超时）。
4. 每条格式：`调用方 → 被调方 ／ 契约位置（章节或节点）／ 缺项 ／ 后果 ／ 编号 C-01…`。

**验收（Gate T4）**：覆盖所有跨模块边；三类问题分别计数；每条能指出"契约在哪份文档哪一节缺失或只写了一半"；孤儿与无主必须给出判定依据（全文检索无调用方）。

**禁止**：以"同一份文档内顺承"冒充契约；把容器节点（如"三抽屉"）当成接口。

### T5 · 双向需求覆盖 ＋ 总报告

**文件**：`docs/reports/audit-wo-ultimaagent-20261113-0056.md`

**写什么**：
1. **正向覆盖**：R-01~R-80 每条 → 归属模块 ＋ 落点（基线章节或节点路径）＋ 验收口径，三列齐才算覆盖；缺任一列标"未落地"。
2. **反向覆盖**：树节点与盘点 27 项 → 是否有需求来源（R 编号）；无来源标"自造能力"，并列清单。
3. **分级汇总**：BLOCKER（链路跑不通）／HIGH（跑通但会坏）／MED（口径不全）／LOW（文案）四级，逐条编号并给一句话修法。
4. **去重声明**：明确本轮新增条数，与 48 条已知（0055 五条＋盘点 27＋缺口复核 16）逐条对照说明为何不重复。
5. **未覆盖声明**：写清没查什么（如代码实现、运行期实测、像素渲染），不写"预计通过"。

**验收（Gate T5）**：80 条 R 全表出现；反向清单可数；四级分级计数相加等于总数；去重声明逐条可核；结论一句话（通过／有条件／不通过）＋最高严重度。

**禁止**：无结论；用汇总掩盖单条缺失；把"文档没写"与"设计不存在"混用（须区分"未定义"与"定义了但错"）。
