## 第 4 段 · 总验收

### A 类（自动机检）— 命令 + 期望输出

1. **解释器断言**：`tools\venv-openjarvis\Scripts\python.exe -c "import sys;print(sys.executable)"` → 输出路径含 `venv-openjarvis\Scripts\python.exe`。
2. **单 run 全产物断言**：机检脚本对 `run/<id>/` 检查 `kws.json`、`capture.wav`、`capture.meta.json`、`asr.json`、`brain.json`、`reply.txt` **全部存在**，且各 `upstream_ref` 逐段可解析、哈希匹配 → 退出码 0，逐项打印 PASS。
3. **反假通断言**：`capture.meta.json` 设备名字段非 file；`brain.json.input_text == asr.json.text`；`reply.txt` 引用 brain.json id。任一不符 → 退出码非零并指明字段。
4. **参数基线断言**：`config/` 与代码 KWS 参数 vs 基线文档逐项相等 → 无 diff 输出即 PASS。
5. **解释器路径复检**：机检脚本自身打印实际解释器路径，与期望路径逐字比对。

### B 类（需人在场）— 留证方式

- **在场者执行**：在真机上开口说唤醒词 → 说一句话 → 等回复。
- **留证**：run 目录内的 `kws.json` 与 `capture.meta.json` 即在场者当时产出的**机器记录**；在场者在 `run/<id>/attest.txt` 写明设备物理位置、时间、本人执行了 S1/S2、签名。
- **双证据交叉**：机器产物（`kws.json` + `capture.meta.json` 的实时性）+ 在场者 `attest.txt`。**任一份缺失即判该次真机门未闭合**，不接受"口头说跑过了"。

## 5. 残留风险（已知，不阻塞下发）

B 类的"实时性"只能靠 `kws.json` 时间戳 + 在场者 attest 间接证明，无人值守下无法根除；已在第 4 段明确不接受口头证据，但若在场者与执行者串通仍可能伪造 `attest.txt`——此为本类需求的边界，不再在本工单内过度设计。

**环境边界（方案 A5）**：若验收环境本身无可用音频输入设备，B 类环节无法执行。此时**只能显式标注 BLOCKED 并记录边界点，不得降级成"离线音频冒充"**。
