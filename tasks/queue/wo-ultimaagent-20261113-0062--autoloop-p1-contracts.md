### T2 · §27.1 M3 指令数据分离

**文件**：`docs/specs/next-感知交互参数基线-20261113.md` §27.1、`scripts/tests/test_event_schema.py`

**写什么**

字段表：

| 字段 | 必填 | 契约 |
|---|---|---|
| `id` | 是 | 事件稳定标识；仅作追踪，不携带执行权限。 |
| `type` | 是 | 事件类别；必须来自本地登记枚举。 |
| `subject` | 是 | 仅允许正则 `[A-Za-z0-9#._:/@-]+`。 |
| `summary` | 是 | 只落资料文件，不拼入执行提示词。 |
| `detail` | 否 | 只落资料文件，不拼入执行提示词。 |
| `link` | 否 | 仅纯 ASCII；只作资料引用，不授予访问权。 |
| `hops` | 否 | 非负整数；缺省与递增语义由 §27.2 唯一规定。 |

映射规则：

1. 入站事件先做“未知字段拒绝”，再校验白名单字段的类型与字符集；调用方不得通过字段顺序或嵌套对象旁路。
2. `summary/detail` 写入资料文件后，只把资料文件引用交给后续本地装配；不得把原文自动并入 prompt。
3. `access`、`cwd` 以及任何未列字段一律拒收，返回 `rejected:unknown_field`；执行上下文只能由本地可信配置补齐。

负例断言：

1. 构造含 `access` 的事件，断言拒收、返回 `rejected:unknown_field`，且未进入派活入口。
2. 构造含 `cwd` 的事件，断言结果相同。
3. 构造 `subject` 含空格或 `link` 含非 ASCII 字符的事件，断言 schema 拒绝且资料文件未创建。
4. 构造合规事件，断言 `summary/detail` 只出现在资料文件，生成的执行提示词不含原文。

**验收（Gate T2）**

1. §27.1 同时存在字段表、映射规则、负例断言，字段白名单集合与本卡逐项一致。
2. 上述负例与合规用例均通过；拒收结果含确定的 `rejected:unknown_field`。
3. 测试证明未知字段在任何执行调用前被拒，资料内容未直接进入提示词。

**禁止**：不得允许 `access`/`cwd` 透传后再清洗；不得把链接视为访问授权；不得在本节定义 `hops` 熔断或卡片幂等。

### T3 · §27.2 M4 跳数与扇出熔断

**文件**：`docs/specs/next-感知交互参数基线-20261113.md` §27.2、`scripts/tests/test_hop_ttl.py`

**写什么**

字段表：

| 字段/派生量 | 契约 |
|---|---|
| `hops` | 入站缺省为 `0`；必须为非负整数。 |
| 本轮最大跳数 | 从本轮被消费事件计算；回执事件使用“本轮最大值 + 1”。 |
| 同轮派活集合 | 以一次规则求值产生的下游候选为边界，最多派出 `3` 项。 |
| 熔断告警 | 记录原因、被截断候选和源事件；不得触发补派。 |

映射规则：

1. 入站未带 `hops` 时按 `0` 处理；派生回执统一写为本轮最大 `hops + 1`，不得由下游自行重置。
2. 当 `hops ≥ 8`，事件只记录、不派活；低于阈值才可进入派活评估。
3. 同轮扇出上限为 `3`；候选超限时按稳定排序保留上限内项，其余截断并告警，不跨轮补发。
4. 深度熔断先于扇出计算，避免已到阈值的事件消耗派活预算。

负例断言：

1. 构造从 `hops=0` 开始的九层链，断言第九层派活调用次数为 `0`，事件仍被记录并含熔断原因。
2. 构造同轮候选超过上限的事件，断言实际派活集合大小不超过 `3`，被截断项可定位且告警产生。
3. 构造负数、字符串或下游重置 `hops` 的输入，断言拒收且不派活。

**验收（Gate T3）**

1. §27.2 同时存在字段表、映射规则、负例断言；缺省、递增、深度阈值与同轮扇出上限均可搜索。
2. 九层链中第九层派活调用次数为 `0`；超限扇出被稳定截断并告警。
3. 非法 `hops` fail-closed；测试不依赖生产队列当前记录数量。

**禁止**：不得只限制深度而不限制宽度；不得把截断项静默丢弃或延迟到下一轮补派；不得使下游覆盖父链跳数。

### T4 · §27.3 M7 卡片 ask.key 幂等

**文件**：`docs/specs/next-感知交互参数基线-20261113.md` §27.3、`scripts/tests/test_card_idempotent.py`

**写什么**

字段表：

| 字段 | 契约 |
|---|---|
| `kind` | 仅 `ask` 或 `fyi`；决定是否允许决策动作。 |
| `ask.key` | 事项稳定标识，不得使用每次发送生成的随机 id；仅 `ask` 必填。 |
| `closed_at` | 表示该事项是否已关闭；未关闭时同 key 不得创建新卡。 |
| `resolve` | 只由有效 `ask` 决策动作产生；`fyi` 永不产生。 |

映射规则：

1. 创建 `ask` 前按 `ask.key` 查询未关闭事项；命中则返回既有卡片引用，不创建第二张。
2. 事项关闭后，同 key 的新事实可创建新卡，但必须关联上一张卡的关闭凭据。
3. `fyi` 不带按钮；任何点击/重复提交均不得生成 `resolve`。
4. 随机展示 id 与 `ask.key` 分离，随机 id 不参与事项幂等判断。

负例断言：

1. 同一 `ask.key` 在未关闭状态连续发送，断言卡片行数不变并返回既有卡片引用。
2. 用不同随机展示 id 包装同一 `ask.key`，断言仍不创建新卡。
3. 构造带按钮的 `fyi` 或对 `fyi` 触发点击，断言 schema/动作层拒绝且无 `resolve` 记录。

**验收（Gate T4）**

1. §27.3 同时存在字段表、映射规则、负例断言；`ask.key` 被定义为事项标识而非随机 id。
2. 同 key 未关闭连发后卡片行数不变；关闭后再发遵循关联上一关闭凭据的规则。
3. `fyi` 无按钮且点击不产生 `resolve`，测试可重复运行。

**禁止**：不得用随机 id 替代 `ask.key`；不得用覆盖旧卡内容伪装幂等；不得让 `fyi` 产生回答或解决记录。

### T5 · §27.4 session_id 与总验收

**文件**：`docs/specs/next-感知交互参数基线-20261113.md` §27.4、T2–T4 测试、基线 diff 证据

**写什么**

字段表：

| 字段 | 必填 | 契约 |
|---|---|---|
| `session_id` | 是 | 非空字符串；作为会话一等字段沿事件/回执信封透传，与 `claim_id` 正交且互不替代。 |

映射规则：

1. §27.4 只定义 `session_id`；创建、派生和回执必须原样透传，禁止从 `claim_id` 推导。
2. 会话切换必须显式提供新值；同一工作声明可跨 claim，但不得因此隐式更换会话。
3. `cancel_observe` 不在本卡，落 §25.10，由 0063 负责。

负例断言：

1. 缺失或空白 `session_id` 的新事件被拒收，且不进入派活。
2. 将 `claim_id` 复制为会话字段或在派生事件中静默更换会话，断言契约测试失败。

**验收（Gate T5）**

1. §27.4 同时存在字段表、映射规则、负例断言，且只承载 `session_id` 契约。
