### T2 · cancel_observe 三值判定表

**文件**：`docs/specs/next-感知交互参数基线-20261113.md` §25.10 段内

**写什么**

在 §25.10 run 级取消映射之后新增下表，字段只挂 run：

| 观测值 | 判定主体与时点 | 判定条件 | 状态/投影结果 |
|---|---|---|---|
| `not_running` | 取消入口在触发时判定 | 无活动进程，且无在途 `cancel_ack` 义务 | 直接落既有 `CANCELLED`，不占 ack 窗口 |
| `running` | 取消执行器在 ack/强杀闭合点判定 | 3s ack 窗口内收到 `cancel_ack`，或缺 ack 后强杀并取得 `ActiveProcesses==0` 凭据 | 落既有 `CANCELLED`，保存 ack 或终止凭据 |
| `unknown` | 取消执行器在 3s ack 窗口结束及强杀观测后判定 | 既无 `cancel_ack`，也无 `ActiveProcesses==0` 凭据 | run 保持最后事实状态，不落 `CANCELLED`；只向队列投影 `CANCELLED_PENDING` |

映射纪律：

1. 三值是 run 层观测结果，不是第九种队列状态，也不是 step/plan 状态。
2. `running` 表示“取消对象确曾运行且终止闭合已有凭据”，不得用“进程仍在”判定。
3. `unknown` 只表示取消观测失败，不表示接单超时；同名不得承担其他语义。

**验收（Gate T2）**

1. 三值表中每个值均有判定主体、判定时点、证据条件与落点。
2. `not_running` 同时要求无活动进程、无在途 ack 义务；`running` 只接受 ack 或强杀后零活动进程凭据。
3. `unknown` 条文同时出现“不落 `CANCELLED`”与“`CANCELLED_PENDING`”，且只挂 run。

**禁止**：不得用 `ActiveProcesses>0` 作为 `running` 成功闭合；不得新增状态枚举；不得更改既有 3s/强杀/零活动进程口径。

### T3 · unknown 投影、解除与告警

**文件**：`docs/specs/next-感知交互参数基线-20261113.md` §25.10 段内

**写什么**

1. 当观测为 `unknown`，run 保持进入取消前的最后事实状态，receipt 不伪造取消完成；只向队列投影非八态标记 `CANCELLED_PENDING`。
2. 下一轮只读对账或再次取消取得 `cancel_ack`/`ActiveProcesses==0` 凭据后，观测转为 `running` 并按既有迁移落 `CANCELLED`，同时保存解除凭据。
3. 连续 `3` 轮仍为 `unknown` 时触发人工介入告警；脚本不得自动改队列，不得把告警本身当作解除凭据。
4. 对账轮次以同一 run 的稳定身份归并；进程查询失败记为不可判定，不得折算为零活动进程。

**验收（Gate T3）**

1. 解除规则明确“下一轮对账或再次取消取得凭据 → 转 `running` → 落 `CANCELLED`”，缺任一箭头均不通过。
2. 连续 `3` 轮仍为 `unknown` 会告警转人工，且执行前后队列内容逐项一致。
3. 查询失败保持 `unknown`；不存在由超时、告警或脚本猜测直接落 `CANCELLED` 的路径。

**禁止**：不得自动修队列、自动假定进程消失或用告警替代终止凭据；不得把 `CANCELLED_PENDING` 加入八态状态图。
