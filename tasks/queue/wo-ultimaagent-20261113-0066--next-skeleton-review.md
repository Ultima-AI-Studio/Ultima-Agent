## 2. 任务明细

### T1 · 报告骨架与依据清单

**文件**：`docs/reports/review-next-skeleton-0066.md`（新建，UTF-8）

**写什么**
1. 段序固定为：§1 结论 ／§2 骨架一句话概括 ／§3 六块边界互斥检查 ／§4 跨模块契约闭合检查 ／§5 §25 主链接入检查 ／§6 新增问题清单（分级＋坐标＋落点）／§7 与 0056 的关系（沿用项 vs 新增项）／§8 未决与建议落单 ／§9 自证。
2. 依据清单逐项列出实际读取文件与行区间（基线章节号与行号、架构页行区间、架构树节点数来源）。
3. 每完成一个 T 即把证据追加进报告，禁止最后一次性补写。

**验收（Gate T1）**
1. 报告文件存在，九段标题齐全且顺序与上文一致，可 `grep` 到每个段标题。
2. 依据清单中每个路径真实存在（命令输出留证）。
3. 每条对基线内容的引用都带章节号或行号，不得只写「基线规定」。

**禁止**：不得在 T1 写结论；不得把报告写成架构页的转述。

### T2 · 六块边界互斥检查

**文件**：同 T1 报告 §3

**写什么**
1. 六块（Core／Senses.Voice／Shell／Surface／Memory／Middleware）＋ Console ＋ 治理⑤，逐块给出三列判定：**越界风险／职责缺口／与他块重叠**。
2. 判定必须落到具体条款：写明该块职责原文（章节号或架构页行号）、被谁侵入或侵入谁、以及"如果两边都实现会发生什么"。
3. 特别检查三处已知高危边界（只要求你判断其设计是否已闭合，不要求你提出实现）：
   - 谁可以起进程：Shell 唯一，核对 Console／Middleware 是否有绕开路径的描述。
   - 谁定义八态：Middleware.state_machine 唯一，核对 Console／Surface 是否有定义性表述。
   - 谁写记忆：Core 唯一裁决，核对 Memory.writer 与 Console 是否有并列写权。
4. 每块至少一条结论，用词固定为「闭合／有缺口／有越界」。

**验收（Gate T2）**
1. 八项（六块＋Console＋治理⑤）各有三列判定，缺一列即不通过。
2. 三处高危边界各有独立结论，且均带原文坐标。
3. 「有缺口／有越界」项必须写明缺什么、谁侵谁、影响是什么，不得只给标签。

**禁止**：不得用「基本清晰」「大体合理」代替判定；不得把架构页原文抄一遍当作判定。

### T3 · 跨模块契约闭合检查

**文件**：同 T1 报告 §4

**写什么**
1. 列出骨架中所有跨块交互（至少覆盖：Voice→Core 对话、Core→Memory 写入与检索、Core→Console 计划、Console→Middleware 派发、Middleware→Shell 进程、Middleware→Surface 呈现、Console→Surface 呈现、治理⑤→各块的约束施加）。
2. 每条交互给三态之一：**有唯一主文／无主文／两处主文**，并写主文位置（章节号或卡号）。
3. 对「两处主文」必须点出两处坐标并说明哪一处应让位；对「无主文」必须写明缺口落在谁的域。
4. 单列一节说明：本骨架是否已具备「一个事实只有一个可写副本」的结构条件（写口唯一性），给出可机检的判别句。

**验收（Gate T3）**
1. 跨块交互条目不少于上文八类且逐条有三态判定，未判定条目数为 0。
2. 每条三态判定均带主文坐标；「两处主文」项均指明让位方。
3. 写口唯一性给出明确结论与可机检判别句（指明查哪个文件、哪个字段）。

**禁止**：不得只统计数量不给坐标；不得用「后续工单处理」跳过无主文项。

### T4 · §25 主链接入检查

**文件**：同 T1 报告 §5

**写什么**
1. 对基线 §25.1～§25.11 逐节标注：归属模块（或「跨块，主文在此」）＋该节是否给出可被下游消费的接口形态（有／无）。
2. 标注不出来源的节，直接记为缺口并写明「缺归属」。
3. 检查 §25 与六块之间是否存在「同一契约在 §25 与别节各写一半」的情形：逐条列出、给两处坐标、判让位。
4. 检查 §26／§27 的预留位置是否与本骨架的模块划分对齐（只判位置，不判内容）。

**验收（Gate T4）**
1. §25 每一小节都有归属标注或缺口标记，未标注节数为 0。
2. 「各写一半」项逐条带两处坐标与让位结论。
3. §26／§27 位置判定给出结论（对齐／需调整位置）。

**禁止**：不得把「§25 已写完」当作接入闭合；不得跳过 §25.10、§25.11。

### T5 · 结论、未决与自证

**文件**：同 T1 报告 §1／§6／§7／§8／§9

**写什么**
1. §1 结论只允许三档：**通过／有条件通过／不通过**，附一句话理由与最关键的三条证据坐标。
2. §6 新增问题清单：每条含严重度（BLOCKER／HIGH／MED）、坐标、证据引文、影响、建议落点（哪一节／哪张卡）；无坐标不计入。
3. §7 明确区分：沿用 0056 的条目（写 `沿用 0056-<编号>`）与本次新增条目，各自数量以清单实际统计为准（不得写死预期数）。
4. §8 未决项：需 Owner 拍板的点、不能由评审判定的点，各给承担方。
5. §9 自证：逐 T Gate 结果＋命令输出；抽检回读不少于 5 条坐标（坐标→原文→一致／不一致）；越界声明（基线与架构页／架构树／方案／队列／代码各自是否被改）。
6. 结论行：`T5_GATE=PASS` 或 `T5_GATE=FAIL`。

**验收（Gate T5）**
1. 结论等级三档之一，且与 §6 最高严重度自洽（存在 BLOCKER 却判「通过」即不通过）。
2. 新增问题每条可定位、可落单；「建议进一步研究」类无落点条目不计入清单。
3. 抽检回读不少于 5 条且逐条给出结论；越界声明逐项写「未改」或列明改动。
4. 结论行存在且与 §1 一致。

**禁止**：不得自行提交、打 tag、更新队列或宣布冻结；不得把「建议重构整个架构」作为结论，必须落到具体节／具体卡。
