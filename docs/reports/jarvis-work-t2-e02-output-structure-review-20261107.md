## 当前结构与交付边界

冻结源码 `agent_server.py:372–460,589–655`、`work_navigation.py:499–570,608–693`、`work_tools.py:611–673` 显示：

1. 先按受限工具读取来源页，动态 schema 只发行当前可信来源与证据编号。达到三来源后开放 write；用满 6 次读取后只能 write 或明确“未交付”。
2. 写动作需在一次响应内形成完整 JSON：`action/action_input` → `path/title/sections[]` → `source_id/heading/facts[]` → `claim/evidence_id`。通用契约 3–5 源、每源 1–6 事实；本例只有三个已确认来源可选，实际相位对应三源。事实与引用必须配对，代码 claim 必须含对应操作名。
3. 模型不用重复生成 URL、完整证据卡、行号或最终 Markdown；`resolve_v3/render_v3` 已将来源、锚点、上下文和引用格式还原。交付格式与模型输出结构已经分开。
4. 只有完整原生 stop、完整 JSON、严格 schema、扫描与实际 SDK 工具调用通过后，才会进入研究写入器。写入器先验证来源/事实绑定，渲染并调用既有 FileWrite，逐字节读回；随后引擎复核文件，再放行一次 ACK。片段落盘不能算完整交付。

因此，本次失败发生在研究工具 dispatch 之前，不是已写文件丢失，也不是 Markdown 渲染或 ACK 失败。当前末态“本次研究未交付。”是如实回执，应保留。

## 找到的结构风险与反证

**字符串生成上限与接收上限不同。** 严格 schema 有 title/heading≤200、claim≤2000 等 maxLength；`agent_server.py:236–260` 的 sampler 投影会移除 maxLength，代码 claim 投影中还有可扩展的 `*`。它们可能让某个字符串持续增长，但没有正文，不能把该可能性当作两例的直接根因。

**不能简单恢复 maxLength。** 旧 source7 的真实请求曾返回 HTTP400；保存的语法错误明确指向重复规则复杂度，包含 claim 的 char{1,2000} 和 final 的 char{1,1000}。旧 schema/GBNF 哈希已重新核对。此历史证据解释当时为何只从 sampler 移除长度，不证明任何新紧凑约束都会失败。未来需要同版本转换器的离线证据，不能原样恢复旧大上限。

**“提示更短”尚未解决问题。** 0421a54 已把实际输出预算写进共享阶段提示，生成与重放都核对；本例仍在同一拒绝点结束。不能从 content_chars 增加认定改善或退步，字符数不是模型 token 数。

**重复结构确有开销，是否主因未知。** 只用于算字节的 ASCII 占位对象：三源各 1/3/6 条事实，总 JSON 分别 381/681/1131 字节；扣掉占位正文后结构为 374/668/1109 字节。这些并非真实响应，不符合事实验收，也不是 token 估计。不能据此直接删除标题、缩短键名或减少事实数量来宣称足够。

**关闭思考的请求参数已经存在。** 原生 leaf 明确发送 think=false、stream=false、truncate=false、shift=false 和实际 num_predict。因 message 校验在 done_reason 后，旧失败仍不能证明 thinking 字段不存在；需要补字段存在性、长度与摘要，而不是再次修改同一个开关。

**覆盖问题独立存在。** 六次读取集中为 README 四页、两份 TS 各一页，OpenJarvis 来源未读。即使下一次 JSON 不截断，也必须继续核验任务架构、开源接入、项目身份、实现与说明的区别；不能用三个来源标题或每源一条细节代替完整原题。

## 交付方案取舍

| 方案 | 在原约束下的判断 |
| --- | --- |
| 保留完整结构输入、程序渲染、一次受限写入和 ACK | 保留。当前已具备这些机制，应先观察未完成的输入结构 |
| 改让模型直接生成整篇 Markdown | 无证据优于当前方案，还需模型重复 URL/格式；会迁移事实与引用校验契约，不是当前最小修复 |
| 流式显示或把响应片段持续写到最终 research.md | 流式传输不增加 num_predict；部分 JSON 不能授权工具。若将来需要用户进度，可用非交付暂存，但不能替代一次完整提交 |
| 六次读取后，逐来源生成再提交 | 6 inspect + 3 draft + 1 commit + 1 ACK=11 POST；即使将三段各自当写入，仍为10且违反 write1。当前不可用 |
| 更早切换到逐来源暂存，最后一次提交 | 可能作为后续架构方案，但需要重新安排原8次预算、保持输出总额、来源绑定/原题覆盖和最终一次提交；并非这次可直接接入的补丁 |
| 接受 length、修复残缺 JSON、只交付已生成部分 | 会改变既有接受条件与交付语义，不采用 |

本地已接入的 OpenJarvis NativeReAct 解析器要求完整 JSON，SDK 现有工具执行链可复用。无需另造研究引擎；本轮也不改底座或依赖。
