## 2. 新增设计错误

| 编号 | 严重度 | 位置 | 设计怎么写 | 约束/另一处要求 | 会怎样坏 | 一句话修法 |
|---|---|---|---|---|---|---|
| E-01 | **BLOCKER** | 基线 §15.2.1 L565–L576；§二 L37；树节点 33 | 八态包含终态 `CANCELLED`，但迁移表只允许 `QUEUED→CANCELLED`、`BLOCKED→CANCELLED`，`EXECUTING` 只能去 `SELF_CHECK/FAILED` | 基线 §二 L37 要求冲突的写操作“立即取消”；节点 33 承诺“叫停·取消·恢复三键” | 运行中的删除/提交/支付即使用户取消，也无法合法落 `CANCELLED`；实现者只能违反状态机、伪装成 FAILED，或让副作用继续执行 | 增加 `EXECUTING→CANCEL_REQUESTED→CANCELLED`（若坚持八态则用活动子态）及 executor/tool cancel ack、超时强杀和票据终结规则。 |
| E-02 | **BLOCKER** | 基线 §16.2 L748、L760–L765；§16.3 L772–L774 | `n_ctx=4096`，调用层允许上下文截到 **4000 token**，同时 `decision max_tokens=256/512`、`dialog max_tokens=512` | 同一模型上下文必须容纳输入与待生成输出；设计自称“4000 留 96 余量”，但最大输出至少 256，摘要/对话为 512 | 合法的 4000-token 请求加输出预算会达到 4256–4512，超过 4096；可能被服务拒绝、截断系统/工具指令，或无法完成摘要 | 把输入上限改为 `n_ctx - max_tokens - 模板/工具保留量` 的按 profile 动态预算，或提高经实测回读的 `n_ctx`，二者只留一条现行公式。 |
| E-03 | **HIGH** | 架构树 `tree.json` 节点 44；双域规范 §八 L149；基线 §21.2 L1181–L1185、§24.2 L1456–L1464 | 节点 44 把 `sandbox（双层：Job＋写域白名单）` 整体挂在 **Middleware** 工具集下 | 双域门要求 Middleware Windows-only 依赖 **0**；§21.2 又规定碰进程/ConPTY/Job 的实现归 **Shell**，Middleware 只持句柄 | 按树开工会把 Windows Job API 引进跨终端 Middleware，Linux/AR 复用层直接被污染；按基线开工又会与树的模块所有权冲突 | 将 sandbox 拆成 Shell 的 `process_sandbox`（Job/平台适配）与 Middleware 的 `fileDomain/policy`，契约只传平台无关 sandbox handle/result。 |
| E-04 | **BLOCKER** | 基线 §17.2.3 L901–L907；§22.3 L1301–L1310；§22.4 L1312–L1318 | 所有冷卷 95%/离线时进入 `CAPACITY_ALERT`，采集“排队不丢、不失败”，检索/对话照常 | 任务库、日志库与 Memory **物理共用同一 `store/`**；审计日志要求 append-only，外部调用/权限拒绝都必须继续写审计 | 全部可写卷已满/离线时，既没有地方持久化“排队不丢”的任务，也无法追加审计、检查点和对话状态；所谓照常运行会变成未审计写或内存队列丢失 | 预留独立、定额、不可被冷数据吃掉的 emergency journal/queue/audit 卷；预留耗尽时 fail-closed 拒新副作用，而非宣称不丢。 |
| E-05 | **HIGH** | 基线 §14.1 L435–L461 vs §17.2 L842–L905、§24.3 L1466–L1486 | §14.1 仍称现行主存储是**单个** `data/memory/store.db`，60k/300MB 硬顶后逐出最旧，卸载后 `data\memory` 为空 | 后续唯一权威 §17 明令“不是一个大 store.db”，改为分库/分层/分片、冷层无上限、卷扩容；R-12/§16.1 又要求用户数据与权重默认保留 | N-03/N-11 可各自按不同“现行”条款实现：一个建单库并删/逐出，一个建多库不设硬顶并保留；数据迁移、卸载和验收不可能同时通过 | 明确废止 §14.1 的物理形态/硬顶/逐出/卸载门，只保留 SQLite+FTS5+向量作为后端技术；所有现行存储与卸载验收统一指 §17/§24/资产 `keep`。 |
| E-06 | **HIGH** | 详解页 §02 L227–L238；基线 §24.1 L1440–L1454；树节点 46 | 详解页 Console 边界段末仍写“**进程留在客户端域是刻意选择**” | §24.1 明确 Console 迁入 Python 引擎域、与 `queue_engine` 同进程，客户端壳树 Console 进程=0；树节点 46 也写同 pid | 以详解页开工会在 C# 客户端保留/重建 Console，形成第二实现与跨进程状态协议，直接破坏同 pid 和 8756 只读边界 | 删除陈旧句并改为“Console 留在 Python 引擎域；客户端仅经 8756 读视图”，详解页只引用 §24.1。 |
