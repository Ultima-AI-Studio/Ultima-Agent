## §1 结论

**不通过。** 新增问题 3 条（BLOCKER 2 / HIGH 1 / MED 0）：①基线 §14.3 L510 的“`queue-status.json` 仍只由状态机写”与 §19.3 L1127 的 Console“只读写八态”及融合方案 §11 L215 的“Console 只读消费”冲突，写口双主；②§25.11 L1763 要补偿失败直接落 `BLOCKED`，但 §15.2.1 L571–585 的 fail-closed 表没有该来源迁移；③架构树 L201 的 Core“执行顺序控制”与基线 §19.2 L1112 的 Console“调度／优先级／依赖”重叠。按当前骨架开工会在队列写口、补偿终态、计划顺序三处打架。

## §2 骨架一句话概括

六块负责理解、语音、进程、呈现、记忆、执行票据，Console 负责“管”，治理⑤负责横切约束；骨架意图是把“决策／编排／执行／托管／呈现／留痕”拆开，但当前在计划顺序、队列写口、执行端起进程三条边界上仍会发生双主或绕行。

### 3.2 三处高危边界

1. **谁可以起进程：有越界。** 唯一权在 Shell（架构页 §02 L199–202：“唯一允许‘起进程、管进程、收进程’”；基线 §15.1 L531）。Console 在基线 §19.4 L1129–1131 明令不得 `CreateProcess`，因此 Console 侧闭合；Middleware 在架构树 L272 的“本层只按指令起执行端”与 §25.8 L1722 的 `start(prepared) -> run` 没有写明必须经 Shell，仍留绕行路径。影响：双父进程、重复执行、Job 外孤儿。处置归属：**沿用 0056-C-04**，在 §25.8 或独立 host-control 主文明确 `start` 只建 run、OS 进程只能委托 Shell。
2. **谁定义八态：闭合。** 基线 §15.2.1 L554–556 明定唯一枚举源为 `tasks/queue_engine/state_machine.py`；消费者表 L587–594 明定 Console 只做点位投影、Manager 取原值、Shell 不换算、Surface 只映射中文。架构页 §02 L221–223 也把定义权给 Middleware，Console 条 L238 明写“八态只读写、不定义”。这里的剩余问题是“谁可写状态”而非“谁定义枚举”，单列 S-002。
3. **谁写记忆：闭合。** 架构页 §02 L185–188 与 §05 L302 将 Core 固定为“记忆写入的唯一裁决／唯一入口”；Memory 在 §02 L213–216 只承载 `writer` 和三库，基线 §25.2 L1568–1572 通过 `mem.write`/`mem.commit_ack` 分开请求与物理确认；Console 的任务库被基线 §22.2 L1310–1314 明确为任务账，且“Memory 不持有任务数据”。因此 Core 决定、Memory 落写、Console 无记忆并列写权。

### 3.3 T2 新增发现（暂存，T5 汇总）

- **S-001（HIGH）**：Core 与 Console 对“执行顺序／依赖”的定义性表述重叠。坐标：架构树 L195、L201；基线 §19.2 L1112。证据片段：“拆解在此，派发顺序与优先级归 Console”与“多步任务规划与执行顺序控制”并存。影响：计划内顺序和调度顺序各自可写，出现双主。建议落点：架构树 Core“任务编排”节点（L201）改为只产 `plan.schema/depends_on`，执行次序与优先级只由 Console 消费并调度；对应卡 N-01/N-13 边界 Gate。
- **S-002（BLOCKER）**：任务／八态的写口出现两处主张。坐标：基线 §14.3 L510、§19.3 L1127；架构树 L281/L288；融合方案 §11 L213–215。证据片段：“仍只由状态机写”／Console“只读写八态与迁移结果”／“写口在 Middleware、读视图在 Console”。影响：Console 与 queue_engine 可能双写 `queue-status.json` 或 `tasks.json`，丢失更新并制造第二状态事实。建议落点：基线 §19.3 与架构树 Console 节点统一为“Console 只提交迁移意图并读投影；唯一持久写由 Middleware.state_machine/queue writer 完成”，挂 N-13 与 0061 的写口 Gate。

### 4.2 一个事实只有一个可写副本

**结论：当前不具备完整的写口唯一性结构条件。** 记忆事实已经满足“Core 唯一裁决、Memory 唯一物理确认”，八态枚举也只有 `state_machine.py` 一处定义；但任务／八态持久写仍被 Console“读写”与 Middleware/state_machine“唯一写”两套表述同时主张（#13，S-002）。在这条消歧前，拿骨架开工会自然长出双写。

**可机检判别句**：对 `tasks/queue/queue-status.json` 中每条任务的 `state` 字段，持久写调用点只能归 `tasks/queue_engine/state_machine.py`（或其唯一 queue-writer 适配器）一处；Console 源码对该文件及 `state` 持久化字段的直接写调用计数必须为 `0`，Console 只能提交迁移意图并读取投影。任一 Console 直写命中或第二 writer 命中即判写口不唯一。
