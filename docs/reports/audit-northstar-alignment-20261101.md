## 1. 卡点诊断：为什么"一直没进度"

- **实证**：2026-10-30 一天内 daemon 重启 7 次（L24-L33），卡点全部是 **Windows 音频栈外围工程问题**：
  - MME 句柄驱动级半死（L25）、端点音量漂移到 6.3%/31.5%（L27/L32）、MME 播放/采集同 hostapi 并发欠载（L31）、WASAPI 设备索引漂移（L31 基线勘误）、USB 麦物理声学耦合（L28）、冷启动 68s（L30）、CV3 克隆音色被 Owner 否决（L30）。
- **结论**：**没有任何一个卡点是"Agent 能力做不出来"**。能力早已通过真机验证（L30/L33：唤醒→识别→意图→回复全对）。"什么能力都不行"的体感，实际是"被一条音频链路拖住，一个版本都推不出去"。

|---|---|---|

## 3. 破局原则（治"卡四五天没结果"）

1. **冻结定义改掉**：冻结 ≠ 所有问题修完，= 已知问题列表化 + 版本打 tag。已知遗留（#133、音量漂移、冷启动 68s）随版本一起发布并登记，不再无限深挖。
2. **音频深坑不再硬啃**：播放/采集互斥已收口（L32）；端点音量用开机探针自愈（L27/L32），"自愈"优先于"根因深挖"。
3. **第一版本即发布**：KWS 基线 + ASR + sherpa TTS（44100Hz 同源）链路已通，锁定为第一冻结版本范围，先让进度"推得动"。

## 4. 架构判断（与主流 Agent 产品对齐）

- **产品同构**：ChatGPT/Codex/豆包/OpenClaw/UltimaAgent 本质同构——模型大脑 + 感知 + 决策循环 + 工具行动 + 记忆的闭环，只是外壳与交流方式不同。**先对齐架构，再谈模型。**
- **模型接入**：本地/云端对上层无差别（Ollama/vLLM 均兼容 OpenAI 协议），模型问题不是当前焦点。
- **评估对象**：业界基线是"模型+harness 对"（UNU《Engineering and Governing the Agent Harness》，2026-07），10 个运行时模式可直接作完整性清单：有界迭代 / 只读并行 / 受控写入 / 两阶段上下文压缩 / 大工具输出持久化 / 可恢复会话 / 轨迹保留 / 工具权限范围化 / 生命周期钩子 / 提供商抽象。
- **主脑选型**：qwen3-8b-uncensored（新架构、工具调用评测强、速度快）适任主脑；**8B 能力≠约束可靠**（uncensored 版移除 refusal 层，边界判断更依赖应用层约束栈）；14B 留库备用（分层路由空间），不删。
- **工具接口原则**：Agent 工具接口**宜精不宜多**（接口数量是选择负担，选型看工具调用质量而非接口数）。
- **OpenClaw 定位**：优秀参考架构（本地网关 + 任意 LLM + 工具 + 多渠道 + ACP 协议），但 Node/WSL2 栈、无语音能力、项目年轻 → **只借鉴不整体替换**，做半天 POC 验证可嫁接点。
- **未来演进**：短期两层（主脑 + 外部顾问）→ 本地大模型接管通用层 → 外部层转型专用能力池（视频/小说/图像按任务路由），主脑永远是调度者。

## 5. 北极星双层定义（2026-11-01 Owner 认可升级）

**愿景层（不变）**：贾维斯形态——随时在场 / 听懂你 / 替你做事 / 不打扰 / 有记忆（北极星定位原则不动，开源项目只作接线方式参考）。

**工程层（升级验收方式）**：借鉴 DeepSeek Super-agent 四关键词（连续/高效/主动/持久）组织验收，五条验收线并入四维：

| 工程维度 | 对应验收线 | 验收口径 |
|---|---|---|
| 连续 | 随时在场 · 有记忆 | 唤醒即响应（热机 ≤18s）；跨轮上下文持续；中断可恢复 |
| 高效 | 替你做事 | 工具调用正确率达标；一次到位；成果可验收 |
| 主动 | 不打扰 | 主动性 observe→auto 分级；该出手时出手、该安静时安静；需人时结构化单独提问 |
| 持久 | 有记忆 · 随时在场 | 会话/任务/偏好持久化；重启可恢复；参数冻结不突变 |

结论：**目标不变，验收框架升级**；北极星上线任务清单按此框架逐项打勾推进。
