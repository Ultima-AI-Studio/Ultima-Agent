# UltimaAgent 主脑提示词策略评估（主动推进型模板）

> 评估：2026-11-01 豆包主脑 ｜ 对象：用户提供《Ultima Agent 主动推进型系统提示词模板》（对齐 G-TASKFLOW-001）
> 结论：**分层使用**——模板整体属"执行端/编排层"提示词；8B 主脑用轻量约束版，不整段嵌入。

---

## 一、模板的本质定位

- 模板主张：接收终极目标 → 自主规划/执行/排障/闭环 → 最小化用户干预，只交付结果。
- 这描述的是**外层编排/执行端**（Codex 派发、UltimaManager 托管、G-TASKFLOW-001 的执行侧），不是"对话主脑"。
- 模板里"自动登记工单、多模型调度、解析输出结构、切换第三方视角审计"——全是 harness/编排系统的职责，8B 主脑既不拥有这些工具，也不存在"编排系统解析"这层。

## 二、为什么不整段嵌入 8B 主脑

| 风险 | 说明 |
|---|---|
| 上下文挤占 | 8B 上下文有限；2000+ 字模板挤占对话空间，反而削弱"听懂你" |
| 幻觉式承诺 | 8B 会"假装"已登记工单/已调度模型/已自主修复——正是回答约束要防的"瞎回答"形态 |
| 与约束栈冲突 | 模板鼓励"自主闭环、不等确认"；意图路由门+校验器是"宽进严出、防自由发挥"。叠加后模型更爱编造推进，校验器压力放大 |
| 无沙箱自主修复 | "遇阻自主决策直接修复"对本地语音 Agent 危险——有文件/系统权限，无沙箱；重大风险必须同步用户（北极星"不打扰≠不反馈"） |

## 三、值得保留到主脑版的部分

- 输出结构约束（≤2 句 / 无营销 / 带 grounded 标注）——与工单 D 约束解码 {reply_text,confidence,grounded} 同向；
- 禁止幻觉：不确定标注"待验证"——与回答校验器同向；
- 对齐 G-TASKFLOW-001 的轻量说明（不要求模型执行，只要求输出符合流程语言）。

## 四、分层落点（建议）

| 层 | 用哪个 | 职责 |
|---|---|---|
| 执行端（Codex/托管） | **模板完整版** | 自主规划执行闭环、登记、审计、冻结（G-TASKFLOW-001 执行侧） |
| 8B 主脑（语音对话） | **轻量约束版**（jarvis.md 角色 + 五条软约束 + 输出结构 + 防幻觉） | 听懂 + 回答 + 被约束；不承担编排职责 |
| 未来主动推进 | harness 层 Trigger/Thread（对齐 DeepSeek Super-agent） | "自动续跑"由外层调度，主脑保持专注 |

## 五、若用户要"主动推进"体验

正确路径不是给 8B 加"自主闭环"指令，而是：把主动推进放进**外层**（事件触发/自动续跑），8B 保持"听懂-回答-被约束"，由外层决定何时唤醒、何时推进。需要时可按此裁剪一版"UltimaAgent 主脑专用精简版"。
