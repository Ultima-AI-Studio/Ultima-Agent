## 一、目标

在 8 锚点 HUD 之上增加**全息人物**内容载体：语音交流时以半身像出现在左上，娱乐状态以全身像出现在屏幕中央。人物为 ChatGPT + Blender 产出的 3D 资产，HUD 的 WebView2（HTML 层）用 Three.js 渲染，SSE 8756 事件驱动动画状态。

**定位**：内容层增强——不占用新锚位、不改变 8 锚点布局结构，复用现有锚位（左上临时位 / 中央透传区显式占用例外）。

---

## 二、三态设计（Owner 拍板）

| 状态 | 触发 | 人物呈现 | 锚位 | 显隐规则 |
|---|---|---|---|---|
| ① 待机态 | 无交互 | 人物**不显示** | — | 不打扰原则；人物永不出现在边缘常驻位 |
| ② 交流态 | 语音交互中 | **半身像**（头肩胸，聚焦口型/表情/手势） | 左上临时位 + 左中 Agent 反馈区联动 | 说话即现、静默即收（与底部 ASR 区同显隐逻辑）；左上系统状态自动让位压缩 |
| ③ 娱乐态 | 用户主动唤起（如"贾维斯出来跳个舞"） | **全身像**（完整身形演出，跳舞/节目） | 中央透传区显式占用 | 静止场景专用 + 显式唤起 + 极速收起（语音/手势/注视离开）；安全档（移动场景）自动禁用；退出即恢复中央透传 |

**半身/全身关系**：同一 3D 人物的两种镜头裁切，不是两套资产——Blender 绑定全身骨骼动画，交流态相机裁到胸口以上（半身），娱乐态放开全视野（全身）。口型/表情动画两态共用，切换平滑。

## 三、口型同步技术选型（Owner 拍板：成熟方案拼装，不自研）

**结论**：口型同步领域成熟，采用现成方案集成选型 + 接驱动数据，不碰核心算法，不发明任何机制。

| 方案 | 类型 | 输入→输出 | 角色 |
|---|---|---|---|
| **Rhubarb Lip Sync** | 开源 CLI（MIT） | 音频/文本 → viseme 时间轴 | 离线 viseme 首选（纯 CPU、无网络依赖） |
| **OVRLipSync（Oculus）** | 开源库 | 音频实时 → viseme 权重 | 交流态实时驱动 |
| **NVIDIA Audio2Face** | 商业工具 | 音频 → 3D 面部动画 | 娱乐态节目预制作可选 |
| ~~自研算法~~ | — | — | **禁止**（已拍板） |

**驱动链路**：

```
TTS 声音/文本
   ↓
[现成 viseme 引擎]（Rhubarb 离线 / OVRLipSync 实时）
   ↓ viseme 序列 + 时间戳
[Three.js 嘴部 blendshape 驱动]（行业标准）
   ↓
人物半身像张嘴闭嘴
```

**对 Blender 资产硬要求**：模型必须带**嘴部形态键（blendshape）**（张嘴/闭嘴/咧嘴/嘟嘴一组基础嘴型）——正常 Blender 人物建模都有；没有形态键，口型同步无从谈起。

---

## 四、Blender 资产可用性四道门（验收清单）

| 门槛 | 要求 | 达不到的后果 |
|---|---|---|
| 导出格式 | glTF/GLB（首选）或 FBX | .blend/OBJ 需转格式；OBJ 无骨骼动画基本重来 |
| 骨骼 + 动画 | 带骨骼绑定（rig）+ 口型/表情/手势动画剪辑 + 全身舞蹈动画剪辑 | 静态模型无法说话对口型，需重新绑定 |
| 面数预算 | 几万面以内（WebView2 跑 WebGL，透明窗口性能预算紧） | 高模卡顿，需减面/LOD |
| 风格匹配 | 全息半透明材质 + cyan 发光描边（符合 UI 哲学） | 实心高模与 HUD 风格冲突，需重做材质（风格兜底在 HUD 侧着色器） |

**与 ChatGPT 协作要求**（当作素材供应商下需求）：输出 glTF/GLB；带骨骼 + 说话口型动画 + 基础表情/手势；全身舞蹈动画单独一条剪辑；全息半透明风格（风格兜底在 HUD 侧）。

---

## 五、技术路线（V1，Owner 拍板）

```
ChatGPT + Blender 建模/绑定动画
   → 导出 glTF/GLB（骨骼+blendshape+动画剪辑）
   → HUD WebView2 内 Three.js 渲染（HTML 层天然支持，不动原生壳）
   → SSE 8756 事件驱动动画状态
     （speaking→口型/表情、listening→待命、task_advance→动作切换）
   → 统一调试（资产接入 → 驱动接线 → 端到端效果调优）
```

**V1 路线原则（Owner 拍板）**：成熟方案拼装 → 最后统一调试。禁止自研口型/面部动画算法。
