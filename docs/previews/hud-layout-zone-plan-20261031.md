## 一、设计原则

1. **按功能分位置**：每个锚点承载一个明确功能语义，不堆内容、不混职责。
2. **极简**：无任务 → 任务窗空/隐藏；任务已完成 → 自动清空，不驻留历史。
3. **常驻 vs 临时**：顶部/左上/右上为常驻位（边缘轻量）；左下/右下/左中/右中/底部为按需显隐位（无需求即不占画面）。
4. **唤出方式**：由 Agent（语音/指令）唤出与收起，不主动打扰。
5. **去繁**：签名、审批等管理操作不进入 HUD 展示（审批口径见 §四.4，2026-10-31 已定稿）。
6. **不打扰基线**：透明 HUD、可鼠标穿透、透明度三档（0.14/0.55/0.85）保持现有能力。
7. **AR HUD 显示哲学（不可破基线）**：边缘常驻 × 按需显隐 × 中央零遮挡——顶部/左上/右上为边缘常驻位（极轻量、透明度可调）；左下/右下/左中/右中/底部为按需显隐位（无需求即不占画面）；屏幕中央永远透传现实，信息只贴边缘。
8. **交流态显隐**：底部仅在与 Agent/对方交流时显示（ASR 转写文字；未来实时翻译显示对方内容+直译结果，可同步语音翻译），静默时隐藏。
9. **全屏幕统一范式（Owner 拍板 2026-10-31）**：无论何种屏幕形态（Windows 桌面 / AR 眼镜 / 平板 / 其他设备），Ultima Agent 一律采用本 8 锚点屏幕布局；布局为跨端统一基线，不做按端各自设计。
10. **AR 安全基线（Owner 拍板 2026-10-31，纳入不可破约束）**：
    - 中央视野永远透传现实，0 遮挡、0 信息；
    - 边缘常驻区信息密度上限 ≤3 信息点/区（暗光/强光环境均不构成视觉干扰）；
    - 临时唤出窗（任务窗/内容窗/反馈窗）必须支持极速收起（语音/手势/注视离开），移动场景避免长占视线；
    - 安全模式档：移动场景（行走/骑行/驾驶）默认最低密度 + 安全档透明度 0.14；高密度/醒目档（0.85）仅限静止场景。
11. **高频上正中，低频收角落（人性化工程）**：时间/天气等每天必看的高频信息放顶部正中；系统状态等"出问题才看"的低频备查信息收左上角；右侧=用户主动唤出（查询/浏览/展开解读）；左侧=Agent 主动推送（反馈区）；右下=即时消息（微信/QQ/Telegram 新消息提醒，来消息才显示）。
12. **无边框气泡形态（Owner 拍板 2026-10-31，形态基线）**：四角壳锚位**不是卡片框**——默认无边框、气泡/浮窗感（轻量悬浮、半透明、无描边卡片）；**置顶（大头钉）时显示边框作为状态反馈**，取消置顶恢复气泡态。AR 状态尤其如此——带边框窗口影响视线。
13. **右上角 = 天气常驻位 + 单功能互斥切换（Owner 拍板 2026-10-31）**：右上角默认=天气（无边框气泡常驻位）；**右上角需要显示其它内容（如导航）时，天气互斥挪到顶部中间区**（同一时刻天气只在一处，不双驻位）；功能切换由 Agent 语音指令驱动，不常驻全功能。
14. **消息气泡上顶消失（Owner 拍板 2026-10-31）**：即时通讯/简讯等消息以气泡队列呈现——**上限 10 条**，新消息一条一条从下往上顶，越往上越淡（第 10 条 ≈20% 不透明度），顶出后逐条消失；不落成固定消息卡片列表。

## 二、8 锚点功能分区总表（Owner 定稿 2026-10-31）

| 锚点 | 功能域 | 常驻/临时 | 内容 | 数据源 |
|---|---|---|---|---|
| 顶部（上中） | 高频常用区 | 常驻 | 时间（每天必看的高频信息）；右上角显示其它内容时承接天气（互斥挪入，迷你显示） | 系统时钟 / 右上角互斥迁入 |
| 右上角 | 天气常驻/单功能切换区 | 常驻（单功能气泡） | 默认=天气（无边框气泡常驻位）；语音切导航→变导航态（方向/坐标/位置/导航）；右上显示其它内容时天气互斥挪顶部中间区 | 语音切换 + weather.query / 定位 / 未来导航 |
| 左上角 | 系统状态区 | 常驻 | 硬件状态、连接信息、上行/下行速率、设备状态（音量/电源/设备在线）——低频备查，异常才关注 | agent_server tick / 系统监控扩展 |
| 左下角 | 任务队列简况 | 按需 | 当前队列 N 项 + 简要进度（队列空即隐） | Manager 18766 |
| 右下角 | 即时消息区 | 按需 | 微信/QQ/Telegram 等新消息提醒（来源+发送者+简短预览，来消息才显示，静默即隐） | 消息聚合接入位（预留） |
| 左中 | Agent 反馈区 | 按需 | Agent 主动推送：日程提醒、重要通知、待办临期、系统告警（Agent 发起才出现） | agent_server 主动事件 |
| 右中 | 主动唤出功能区 | 按需 | 用户主动唤出的内容画布：新闻列表→展开→解读、查机票/查餐厅/搜索等查询结果（用户发起才出现） | 各业务工具 / 搜索 / weather.query 等 |
| 底部（下中） | 交流转写区 | 按需 | 说话时显示 ASR 识别文字；未来接实时翻译时显示对方说话内容 + 直接翻译结果（后续可同步语音翻译） | voice-listen-daemon ASR / 未来实时翻译链路 |

## 三、与现有白龙马 4 widget 的映射

现有实现为 4 widget：w-agent（左）、w-sys（右）、w-msg（中）、w-hb（右）。

| 现有 widget | 现有内容 | 新方案去向 |
|---|---|---|
| w-msg 聊天 + 语音条 | 对话气泡 + ASR 语音条 | 对话部分移除（W2 只出结果原则）；语音条迁移 → 底部交流转写区（含未来实时翻译位） |
| w-sys 心跳/连接 | 连接状态、心跳波形、tok/s、节点/链路 | 左上系统状态区（保留连接 + 扩展硬件/上下行速率/设备状态） |
| w-agent AI 活动 | L1 流（消息/工具调用流） | 并入左中 Agent 反馈区（Agent 主动推送） |
| w-hb 行动日志/思考流 | 工具/命令/文件动作流 | 并入右中主动唤出功能区（任务执行细节/查询结果流） |
| 右上角 | （时钟并入 SYSTEM，无独立内容） | 新增：方向/坐标/位置/导航预留 |
| 顶部 | （原无独立内容） | 新增：时间 + 天气（高频常用） |
| 左下/右下/左中 | （无） | 新增：左下=任务队列简况、右下=即时消息、左中=Agent 反馈区 |

## 四、显示规则（状态机）

1. **无任务**：左中反馈区/右中内容区为空（或整体隐藏），桌面保持清爽。
2. **有任务**：Agent 执行任务时，左中反馈区显示 Agent 主动推送（任务阶段/进度/工具动作/重要提醒）。
3. **任务完成**：状态置为已完成 → 窗口自动清空/收起，不显示历史任务。
4. **审批/签名**：HUD 层一律不出现（Owner 拍板）。审批口径定稿（2026-10-31）：**过程完全自主（AI 主动思考→主动修正→主动优化，中间全程 0 审批），以目标结果为导向，最终提交交付审批为唯一一道审批环节（用户验收/打回）**；展示层永远不带审批界面。
5. **右侧唤起**：用户主动发起查询/浏览时，右中弹出内容画布（列表→展开→解读），极速收起可用（语音/手势/注视离开）。
6. **消息显隐**：右下仅在有新消息（微信/QQ/Telegram）时显示提醒，静默即隐。
7. **右上角单功能互斥切换**：右上角=天气常驻位；语音切换其它功能（导航等）时，天气互斥挪至顶部中间区迷你显示，同一时刻天气只在一处，不双驻位。
8. **置顶才显边框**：所有锚位窗口默认无边框气泡态；置顶（大头钉按钮/右键菜单）后显示边框作状态反馈，取消置顶恢复气泡态。

## 五、落地路径（改造而非重建）

1. 改 `hud-live-four-corner.html`：8 锚点分区 + 左右中三窗（反馈/内容/任务）替换 4 widget 布局。
2. 接 Manager 内核：任务状态走 `127.0.0.1:18766` API（身份校验后读取当前执行任务）。
3. 保留 Agent SSE：`?sse=8756&native=1` 继续承载 Agent 事件/语音/系统状态。
4. 左上系统状态（硬件/连接/上下行/设备）：扩展 agent_server tick 或新增系统监控数据点。
5. 顶部时间/天气 + 右上方向/坐标/位置：weather.query 已有工具，导航预留接口位；消息聚合接入位预留（右下）。
6. 回归验收：透明不遮挡、托盘菜单、穿透/透明度三档、无任务空窗、右侧唤起/极速收起、消息/反馈按需显隐。
