# L9 驻留域两级判定裁决 · 记忆层是否升级为强制驻留

- 时间：2026-11-12
- 状态：**待 Owner 裁决**（默认按现行 spec 执行，见 §五）
- 依据：`docs/specs/plugin-bus-spec.md` §5.4 / §13 / §15、`src/brain/memory/registry.py`、`execution/server/ultima_bus/kernel.py`
- 触发：模块化梳理（inventory v2.1 / plan v3.1）发现同一卸载动作存在两套相反结论
- 执行端：豆包（只落盘记录，不改实现）

---

## 一、事实：存在两级驻留判定，且互不相通

项目里同时跑着两套"驻留"语义，作用于不同粒度：

| 维度 | 域级（粗） | 实例级（细） |
|---|---|---|
| 载体 | `BusKernel`（`execution/server/ultima_bus/kernel.py`） | `src/brain/*/registry.py` 四个自建注册表 |
| 判什么 | 能力**域**（L 层） | 具体**模块键** |
| 白名单 | `RESIDENT_DOMAINS = {"L8", "L10"}`（kernel.py:53） | `_resident` set（memory/registry.py:22） |
| 默认值 | — | `register(..., resident=True)`（memory/registry.py:30）**默认驻留** |
| 有 CLI | ✅ load / unload / switch / rollback | ❌ 无 |
| 有审计 | ✅ 11 类 `_audit` 事件 | ❌ 无 |
| 生产在用 | ❌ `src/` 零引用（入口在 `execution/`） | ✅ scanner / backend / engine / bootstrap |
| 规格依据 | ✅ spec §5.4 | ⚠️ 仅代码 docstring |

`kernel.py` 对 `GuardrailsRegistry|MemoryRegistry|OrchestrationRegistry|SkillRegistry` 的引用次数为 **0**，确认两者无代码级调用关系——是两套并行体系，不是一套的两层。

---

## 二、规格侧：§5.4 只列两域，不含 L9

`plugin-bus-spec.md` §5.4「强制驻留插件」表只登记两个域：

| 域 | 前缀 | 依据 |
|---|---|---|
| L8 | `ultima.guard.*` | 受控执行/越界拦截是安全底线，不可热卸载、不可禁用；卸载需 Owner 特批，期间禁写/禁控制 |
| L10 | `ultima.paradigm.*` | api-contract §2 强制「不得跳过 L10 范式直达能力」，同规则 |

§5.4 末句：总线启动时若 guard/paradigm 缺失或加载失败 → **总线拒绝对外服务（fail-closed）**。§13 安全约束表同口径；§15 试点清单列 `ultima.memory.lite` 为「L9 最小件」。

**L9 从未进入 §5.4 的强制驻留表**——这是规格的明确选择，不是遗漏。

---

## 三、代码侧：实例级默认驻留，且 docstring 写「与 L8 同规」

`src/brain/memory/registry.py`：

- L1 docstring：`「L9 记忆注册表（驻留标记，与 L8 同规）」`
- L14：`class ResidencyViolationError(RuntimeError)`
- L30：`register(..., resident: bool = True)` —— **不显式传参即默认驻留**
- L63-71：`unload()` 命中 `_resident` 时抛 `ResidencyViolationError(f"L9 记忆 '{key}' 为驻留组件，禁止热卸载")`

即：实例级把 L9 视为**与 L8 同等不可卸**，且是默认行为。

---

## 四、冲突：同一动作两套结论相反

以 `ultima.memory.lite`（spec §15 登记的 L9 试点件）做同一卸载动作：

| 判定者 | 结论 | 依据 |
|---|---|---|
| 域级 `BusKernel` | **可卸载** | L9 ∉ `RESIDENT_DOMAINS = {"L8","L10"}` |
| 实例级 `MemoryRegistry` | **禁止卸载** | 键在 `_resident` 中，默认 `resident=True` |

一个说能卸、一个说不能卸，且**两边都不知道对方存在**。

---

## 五、待裁决项（Owner 决定，两侧理由均已成立）

### 选项 A：L9 升级为强制驻留（改 spec + 改 `RESIDENT_DOMAINS`）

**理由**：记忆是"能记得住"的前提。若记忆可热卸载，用户上一句说过的事实会在下一轮丢失，直接违背产品价值机制「意图→编排→执行→组合窗口+语音汇报」中的上下文连续性；且 `memory/registry.py` 已经用代码表达了"与 L8 同规"的意图。

**后果**：
- `plugin-bus-spec.md` §5.4 表加一行 L9，§13/§15 同步
- `kernel.py:53` 改为 `{"L8", "L9", "L10"}`
- 总线要能卸载记忆，须走 Owner 特批流程（与 L8 同强度）
- 运行日志中 `audit.resident.unload.denied` 将开始出现 L9 对象

### 选项 B：L9 保持可重载，改 `memory/registry.py` 默认值

**理由**：记忆的持久化在存储层（`MemoryLayers` 四层结构 + 落盘），不在插件实例。卸载插件后重新加载，历史条目仍在磁盘上，不构成"丢记忆"；而把 L9 拉进 fail-closed 会让总线启动依赖更多前置，可用性成本上升。现行 spec 只列两域，是这个判断的既有结论。

**后果**：
- `memory/registry.py:30` 默认改 `resident=False`，docstring 的「与 L8 同规」须删改
- 需确认卸载/重载后 `MemoryLayers` 能正确重新加载既有 `data/memory` 条目（当前无此测试）
- spec 不动

### 选项 C：不做域级统一，明确两级各管一段

**理由**：两级粒度本就不同——域级管"整个能力域能否下线"，实例级管"某个具体模块键能否被重置"。同时满足不矛盾。

**后果**：
- 需在 spec 明写两级职责边界与优先级（冲突时以谁为准）
- 需加一致性校验：域级判可卸而实例级拒绝时，向上一级报冲突而非静默
- 成本最高（要新增校验与测试），收益是语义最清晰

## 六、默认执行口径（Owner 未裁决前）

**按现行 spec 执行 = 选项 B 的现状**：L9 不在强制驻留域，域级判可卸。理由：spec 是权威源，代码 docstring 不构成规格；在 Owner 明确裁决前，不以代码默认值反向覆盖规格。

**但两处必须同步标注**（否则仍是"分不清"）：

1. `src/brain/memory/registry.py` 头部 docstring 的「与 L8 同规」加注：「本句描述实例级默认策略，尚未获 spec §5.4 认可，待 pd-20261112 裁决」
