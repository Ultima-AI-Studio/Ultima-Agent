## 一、背景与触发事实（2026-11-13 实测）

1. 机上实有 **12 条** UltimaAgent 计划任务（方案原文写"无条目"）：10 条 queue-observer 一次性遗留（建任务不回收）、`UltimaAgent-Preload`（ONLOGON，实证 `launch.ok=false` + `WinError 2`，解释器错指向 Doubao sandbox_runtime，**从未真正拉起 voice 栈**）、`UltimaAgent-Watchdog`（**Running**，pythonw 跑 `scripts/watchdog-loopguard.py`，守 8756）、`UltimaAgentTrackerLive`（Disabled，开发工具）。
2. Phase 2（`9febf442`，已冻结）已让 HostShell 具备：Job Object 托管（宿主死 → 子树内核回收）、`ChildProcessSupervisor` 拉起子进程（`UseShellExecute=false` + `CreateNoWindow=true`）、`ReadinessProbe` 对 `http://127.0.0.1:8756/health` 的探活。
3. 外部 watchdog 的实质职责仅四项：20 秒间隔探活 8756、不健康则经 `scripts/start-agent-server.ps1` 拉起、连续失败 3 次停手并冷却 300 秒、写 `watchdog.log`/`watchdog-events.jsonl`。
4. 终端弹窗根因不在 watchdog 本身（pythonw 无控制台），而在：① schtasks 调度链路（`/TR` 过 cmd、`/Run` 闪 conhost）；② 经 `start-agent-server.ps1` 的 PowerShell 拉起路径；③ venv launcher 在 `DETACHED_PROCESS` 下忽略无窗标志（`scripts/fix-venv-launcher.ps1` 已记录）。

## 二、裁决（A 方案）

**用户安装包内不创建任何 Windows 计划任务；watchdog 的进程守护职责内化进 HostShell，开机自启改用启动文件夹快捷方式。**

1. **守护内化**：HostShell 新增 `GuardianService`（后台循环，复用 `ReadinessProbe` 探活 8756；失败时走 C# 直接拉起 `agent_server.py` 的现有路径，**不再经 `start-agent-server.ps1`**；保持 20 秒检查、连续 3 次失败冷却 300 秒的语义；事件写 `data/logs/guardian-events.jsonl`）。
2. **任务注册表**：新增 `config/host-tasks.json`（托管任务声明，随仓入库）+ `HostTaskRegistry`（运行态：pid/重启次数/最近探活，状态写 `data/host/host-tasks-state.json`）。
3. **外部 watchdog 下线**：`scripts/watchdog-loopguard.py` `git mv` 到 `devtools/watchdog.py`，作为**开发机手动兜底**（不装 HostShell 调试 voice 栈时使用）；删除 `UltimaAgent-Watchdog` 计划任务，**不做同名重建**。
4. **开机自启**：新增 `AutostartEntry`，在启动文件夹（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`）放指向 HostShell 的 `.lnk`；无控制台、无 UAC、无 schtasks。
5. **运行态面板**：HostShell 内新增任务管理器面板（WebView2，复用 `WebMessageReceived` 双向范式），展示托管任务状态/重启次数并支持手动重启、停用；**未来挂载点 = 四角壳左下锚位**（"任务队列简况"，见 `docs/plans/manager-console-combined-plan-20261031.md`）。四角壳 8 锚窗当前仅有定稿方案与静态预览、未实现，本阶段不建锚窗框架。

## 四、明确的非目标与代价

1. **应用崩溃后不自愈**：Job Object 会在应用退出时回收全部子进程，此时无外部进程重启应用，下次登录（启动文件夹）恢复。这是"零常驻外部进程"的固有代价，Owner 已知悉并接受。
2. v1 Guardian 只对 **agent_server（8756）** 做运行期自动重启（与旧 watchdog 对齐）；launch.py/live/worker 的运行期死亡不自动重启，仅在面板呈现，启动期仍由 `ChildProcessSupervisor` 负责。
3. 不实现四角壳 8 锚窗框架；面板先在 orb 主窗体系内交付，数据层与后续锚位共用，不返工。

## 五、切换顺序（防守护断档，工单 T2 强制）

1. 先实现并验证 `GuardianService` 已在跑（事件日志有探活记录）；
2. 再对外部 watchdog 执行 `--uninstall` 删任务、按命令行精确终止 pythonw（禁写死 PID）；
3. `git mv` 脚本到 devtools，不执行 `--install`；
4. 用"强杀 agent_server → Guardian 在一个检查周期内拉起、8756 恢复"做集成实证。
