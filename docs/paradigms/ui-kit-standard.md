# UI 积木规格（UI Kit Standard）

- **版本**：v1.1 · 2026-10-16
- **性质**：范式文件（冻结区，变更走评审）
- **来源**：《图波智能体 · 后端范式共识》第三、四章 + OpenUI/shadcn 调研借鉴

## 1. 核心哲学

1. **UI 是乐高积木，不是成型页面**：标准管"积木规格"，不管"拼装结果"；窗口由智能体按规格现场组装，没有固定页面。
2. **范式唯一 · 主题多样**：范式定骨（规格/组装/流程/汇报/约束不变），主题换皮（同一规格下生成新零部件再组合）；换主题＝换令牌值，组件与组装引擎不改。
3. **选择权在智能体**：把 UI 样式/声音/动效都固定给智能体，它就是"套了 AI 主脑壳的应用程序"；"活"＝智能体在骨不变下自由选择呈现。

## 2. 组件注册与 schema（工程化标准）

- 每个积木组件必须登记到 `docs/specs/registry.md`（M1），带 **props schema**（参数/类型/约束）。
- 主脑/Skill 按 schema 生成组件树，渲染器渲染前校验 props——**安全默认**（无任意代码执行）。
- 借鉴 OpenUI：组件注册表 + defineComponent + Zod 校验 props；借鉴 shadcn/skills：给编码智能体可消费的组件上下文。

## 3. 组件树 DSL

- scene-orchestrator 输出"组件树描述"而非死页面；描述格式参考 OpenUI Lang 思路做**紧凑 DSL**（比 JSON 省 token、响应更快）。
- 组件树 = 积木清单 + 参数 + 布局；渲染器消费组件树生成窗口。
- 流式：内容到达用入场动效，容器平滑缩放（见 motion-director）。

## 4. 组件清单（初始，随 ui-kit 冻结扩充）

窗口 / 按钮 / 开关 / 滑块 / 进度条 / 列表卡片 / 输入框 / 弹窗 / 悬浮球 / 播放器（音乐·电影同一类两个实例）/ 传感器卡片 / 状态标签

- 尺寸、间距、字号层级**跟随宿主系统**（WinUI 3 等），不自造度量体系（见 theme-standard）。

## 5. 强制约束

- 组件未登记 schema 不得使用；渲染前未校验不得呈现。
- 禁止为单一页面写死布局；一切界面由组件树动态组装。

## 6. 原型评审检查清单（强制，I11）

UI 原型/组件交付评审时固定核对以下项，**一次对齐，减少逐轮补需求**（Top 阶段 W4 弹窗 3 次改版的教训）：

1. **尺寸与比例**：宽/高/行列数是否符合要求（一行几列、共几行），是否引用参考对象（如主题设置弹窗的样式）。
2. **标题与层级**：标题/副标题文案、是否换行、层级是否正确。
3. **内容与开关**：条目清单齐全、开关/控件对应关系正确、是否有冗余副标题。
4. **状态与交互**：弹窗/提交等关键动作有明确反馈；无反应/超时/失败态有交代（I12 预演）。
5. **参考对齐**：与指定参考对象（同系列弹窗/主题）的度量一致。

> 评审结论三态：通过 / 需修改（列具体项）/ 重做（方向性不符走变更流程）。

## 8. 全屏幕 HUD 布局范式（8 锚点 + AR 安全基线）

> Owner 拍板 2026-10-31：无论何种屏幕形态（Windows 桌面 / AR 眼镜 / 平板 / 其他设备），Ultima Agent 一律采用本 8 锚点屏幕布局；布局为跨端统一基线，不做按端各自设计。
> 详细方案：`docs/previews/hud-layout-zone-plan-20261031.md`

### 8.1 锚点分工（功能 = 位置，Owner 定稿 2026-10-31）

| 锚点 | 功能域 | 常驻/临时 |
|---|---|---|
| 顶部（上中） | 高频常用：时间、天气 | 常驻 |
| 左上角 | 系统状态：硬件、连接、上行/下行速率、设备状态 | 常驻 |
| 右上角 | 环境/位置：方向、坐标、位置、导航预留 | 常驻 |
| 左下角 | 任务队列简况（队列空即隐） | 按需 |
| 右下角 | 即时消息：微信/QQ/Telegram 新消息提醒 | 按需（来消息才显示） |
| 左中 | Agent 反馈区：日程提醒/重要通知/待办临期/系统告警 | 按需（Agent 发起） |
| 右中 | 主动唤出功能区：查询/浏览/列表→展开→解读 | 按需（用户发起） |
| 底部（下中） | 交流转写区：说话时 ASR 文字；未来实时翻译（对方内容+直译，可同步语音） | 按需显隐 |

布局语义：顶部="此刻"（时间+天气）→ 右上="方位" → 左上="机器健康" → 左下="接下来" → 右下="有人找我" → 左中="Agent 有话要说" → 右中="我要 Agent 办事" → 底部="正在交流"。

### 8.2 AR 安全基线（不可破约束）

1. 中央视野永远透传现实，0 遮挡、0 信息。
2. 边缘常驻区信息密度上限 ≤3 信息点/区（暗光/强光环境均不构成视觉干扰）。
3. 临时唤出窗必须支持极速收起（语音/手势/注视离开），移动场景避免长占视线。
4. 安全模式档：移动场景（行走/骑行/驾驶）默认最低密度 + 安全档透明度 0.14；高密度/醒目档（0.85）仅限静止场景。
5. 审批/签名不进入 HUD 展示层。审批口径（2026-10-31 定稿）：任务过程完全自主（AI 主动思考→主动修正→主动优化，中间 0 审批），以目标结果为导向，最终提交交付审批为唯一一道审批环节（用户验收/打回）。
