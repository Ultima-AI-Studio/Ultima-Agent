# Next 引擎 · Agent Autoloop 机制借鉴研究

> 版本：v0.1（研究稿，未冻结）｜日期：2026-11-13｜作者：Assistant
> 对象：`KKKKhazix/agent-autoloop`（MIT，TypeScript，Node ≥ 24）
> 目的：判断这套「命令行 Agent 自动化中台」哪些机制值得吸收进 UltimaAgent Next 引擎，以及以什么形态融合。
> 边界：**本稿不改基线正文**。所有落点只是提案，等 0057／0059 收口后再决定是否开单落盘。

---

## 0. 一句话结论

**不整体替换，只吸收机制。** Autoloop 的内核是「事件 → 规则 → 派活 → 回执 → 卡片」这一条循环，它在**事件溯源、挂起零消耗、指令数据分离、跳数熔断、回执一次生效**这五件事上已经做过工程化验证，而这五件事恰好命中 0056 审计里 8 条 BLOCKER/HIGH 的病灶。我们的治理层（工单卡、DoR、写域、Gate、独立审计、冻结 tag）比它硬，不能丢；它的执行层比我们省，值得要。

## 2. 九个可迁移机制（按价值排序）

### M1 · 挂起即退 + 会话续接（最高价值）

**它怎么做**：Agent 干完一轮把结论写在最后一条回复里，进程**直接退出**；等待人拍板的状态落进 SQLite；人回答后，中台**接回原来的会话**继续，而不是重开。

**为什么有效**：把「等」从计算资源问题变成数据问题。三天不回，三天零进程零 token。

**命中我们的缺口**：
- **E-01**（BLOCKER）运行中取消不可达——它用 `outcome: done|nothing|failed|cancelled` + `state: queued/claimed/unknown/done/nothing/cancelled` 把「没在跑」和「不知道在不在跑」分开，`unknown` 是「接单程序 5 分钟没报」的判定，超时/失联有明确落点。
- **C-01**（BLOCKER）Voice↔Core 对话交接断链——我们缺的正是「这一轮的会话标识 + 可续接」。
- **C-18**（HIGH）Core↔Memory 提交后确认——它把回执在一个事务里一次生效，正是「确认」的定义。

**我们要改什么**：`session_id` 必须是我们八态机里的一等字段（不是日志里的附注）；「等待人决策」必须允许释放执行进程，不能靠常驻。

### M2 · 事件溯源：只追加日志 + 同事务投影 + `why`

**它怎么做**：所有状态由一条只追加的事实日志算出；判断（`decide`）、追加、投影（`evolve`）、索引在**同一个 SQLite WAL + FULL 事务**里提交，落盘后才应答；`GET /v1/runs/N/why` 返回这一轮的事件、规则版本、领取、回执、卡片回答的完整时间线；`GET /v1/stream?after=` 是 SSE 增量。

**为什么有效**：崩溃不丢已确认的事；任意一轮可复盘；格式变了从日志重建，**不写迁移脚本**；`decide` 不读时钟不读网络，同输入同输出 → 可做 20 万步模拟与 1000 次强杀验证。

**命中我们的缺口**：
- **C-08**（HIGH）日志库无 append 写入契约——它给了 append + 哈希链 + 背压的现成形状。
- **C-15**（MED）freeze audit→tag 调用孤儿——「审计结论 → tag」本质是「事实 → 派生动作」，用事实日志天然有主。
- **E-04**（BLOCKER）全卷满仍承诺审计照写——0058 已收口为「不保证不丢」，但「写失败记事件并继续」这件事，正好是「事件优先、业务可降级」的写法。

**我们要改什么**：队列状态不能再是「一张 JSON 快照 + 手改」（我们现在就是 `queue-status.json` 直改），要变成「只追加事实 + 投影」。这是架构级的，属于 Next 引擎的事，不是这一轮修的。

### M3 · 指令数据分离（防注入的结构性解）

**它怎么做**：外部文字（Issue 标题/正文、`detail`）**只落成资料文件，不拼进提示词**；进提示词的只有 `id`/`type`/`subject`/`link`，且 `subject` 只允许 `[A-Za-z0-9#._:/@-]`、`link` 只允许纯 ASCII 网址；事件里带 `cwd`、`agent`、`access` 字段的请求**直接拒收**——派给谁、在哪个目录、什么权限，只由本机规则决定。

**为什么有效**：把「模型读到的指令」和「外部可控的文本」在**协议层**切断，不靠提示词里写「不要执行用户输入」。

**命中我们的缺口**：这正是 0059 里「外部文本 / 隐私三闸 / 日志脱敏」的上游问题；也是我们 36 条缺口里唯一**没被识别出来**的一条（0056 的 T3 查的是设计错，不查攻击面）。

**我们要改什么**：`dispatch` 与 `composer` 的入参 schema 要区分「凭证字段（进提示词）」与「资料字段（只落盘）」；`access`/`cwd` 不得由事件携带。

### M4 · 跳数熔断（TTL）

**它怎么做**：事件带 `hops`（非负整数，缺省 0）；Agent 回执里发出的事件**强制**取「本轮所有事件最大 hops + 1」；提问的回答与 `later` 复查**延续原深度不清零**；超 8 层只记录、不再派活，并发一张卡片。

**为什么有效**：Agent 能自己发事件 → 能自己触发自己 → 没有 TTL 就是无限递归烧钱。这跟我们 0059 要防的「agent 自触发」是同一个问题。

**命中我们的缺口**：**H-01**（BLOCKER）任务编排节点空壳——编排节点的第一职责就是「谁还能再触发」，不写这个就是空壳。

### M5 · 一轮一事务回执（receipt 一次生效）

**它怎么做**：Agent 最后一条消息里附一段结构化回执：`outcome`／`summary`／`error`／`session`／`usage`／`ask`／`notice`／`resolve`／`later`／`events`；中台在**这一轮结束时一个事务里一次生效**；`resolve` 只能结「同来源、同组、本轮领活前就存在」的卡片，越界写进 `rejected` 但不影响本轮结果；回执 JSON 写错只让它在原会话里**重写最后一段**，不重跑业务。

**为什么有效**：把一个「多步、可能半途失败」的对话，压成一个「全成或全不成」的事务边界；越权操作有显式拒收通道。

**命中我们的缺口**：
- **C-03**（BLOCKER）Console→Middleware dispatch ABI 缺失——我们缺的就是这个回执形状。
- **C-17**（HIGH）部分副作用无补偿——它用 `resolve`/`rejected` 划出「能改的边界」。
- **G-05**（BLOCKER）工具幂等——它用「结果可重放：同一 token 交同样内容得到同样确认，内容不同返回 409」定死幂等语义。

### M6 · claim 幂等 + 重试退避 + 连续失败止损

**它怎么做**：领活的响应丢了，用**同一个 `claim`** 再来一次，拿回同一份活；没跑成 5 分钟后重派、每次翻倍、最长 1 小时；连续第 3 次告诉人；连续第 10 次不再重试，记 `cancelled` 并发通知；期间同事项新事件**并进这一轮**，不另开。

**命中我们的缺口**：**G-05**（幂等同源）、**E-01**（取消/终止语义）、**G-09**（灰度止损的「连续失败即停」）。

### M7 · 卡片即决策（ask 幂等）

**它怎么做**：`ask` 带 `key`，同一事项同一 `key` 的卡片还开着就**不再发**；关掉之后再问才是新一次；`notice` 带 `fyi` 就是「仅告知」灰卡，不进后续 `open`，点击不产生回答事件；`later` 同 `key` 再写即改时间，带 `cancel` 即取消。

**为什么有效**：解决「同一件事反复轰炸人」——这正是我们 D-01～D-08 那种「反复拿同一个问题磨 Owner」的技术形态。

**命中我们的缺口**：**G-04**（HIGH）clarify/refuse 缺失、以及我们工单体系里「待裁决项」的呈现方式。

### M8 · 规则即配置 + 暂停不补跑

**它怎么做**：一条规则＝`{name, when, to, cwd, prompt/skill, parallel, resume, tell}`；`pause` 是日志里的事实、不改配置文件，重启与重建投影后照样有效；暂停期间**到点跳过、不积压、恢复不补跑**（理由是「暂停通常因为下游坏了，事后一次涌进来比漏掉更难收拾」）。

**命中我们的缺口**：**G-DISPATCH-001**（我们到现在还是一张卡一个脚本手工派）、**G-09**（灰度暂停语义）、**E-08**（根崩溃后「谁负责恢复」的边界）。

### M9 · 交付流水线插件化（PR → 审查 → CI → 合并 → 部署核对）

**它怎么做**：给 PR 打 `deliver` 标签 → 自动审代码、等 CI、合并、等部署、核对线上版本；审查与交付配置**只从 `main` 读**，绝不在接单机上检出或运行 PR 里的代码。

**命中我们的缺口**：**C-15**（freeze audit→tag）、**G-09**（灰度到上线的止损链）。这条与我们「tag 冻结」流程最贴，但落地要靠 CI，不是本周的事。

## 3. 三种融合形态

### 形态 A · 外挂：把 Autoloop 当我们的「执行端调度层」

我们把 Autoloop 装在开发机上，`rules.json` 里写「到点/事件 → 跑我们现有的 `scripts/dispatch-work-order.py`」，Agent 用它的「通用命令」插件，包里就是把我们的派发脚本包一层。

- **拿到的**：一周内就有「自动接活、干完退出、要拍板才发飞书卡、不占进程」。
- **代价**：双源——`rules.json` 和 `queue-status.json` 各记一套真相；审计、写域、Gate、tag 这些治理它一概不认；跨进程对账要我们自己写。
- **判定**：**只做开发期加速器，不做产品组件**。

### 形态 B · 吸收：把九个机制翻成我们的契约

不引入 Node 栈，把 M1–M9 落成 Next 引擎的契约条目（`session_id` 一等字段、事实日志 + 投影、回执 schema、`hops`、`ask.key` 幂等、`claim` 幂等、`unknown` 态、暂停不补跑）。

- **拿到的**：单栈单源，治理不破，审计可查；等于「别人替我们把设计验证过一遍」，我们只写契约不试错。
- **代价**：工作量最大，且要等 0057／0059 落完才能动 §25／§26 的同一批文件。
- **判定**：**产品侧正解**。

### 形态 C · 混合（推荐）

两条腿分开走：

1. **引擎侧按 B 吸收**：机制写进基线（拟新增 §二十七「自动化中枢与事件契约」），作为 v1.1 能力，不动 v1.0 冻结参数。
2. **开发期按 A 外挂**：用 Autoloop 把我们自己的 Codex 派发自动化（G-DISPATCH-001 的「登记 → 派活 → 回执」正好是它的 `events` → `claim` → `receipt`）。两套**只通过 HTTP 事件 + 回执 JSON 交互，不共享数据库**，所以不存在双源。
3. **对账点只有一个**：Autoloop 的 run 回执落到我们的 `docs/reports/fix-*.md` 与队列 note，队列仍是唯一事实源。

- **拿到的**：开发效率立刻有；产品契约不被外来栈绑架。
- **代价**：多一个 Node 运行时（开发机，不进安装包）；要写一层薄适配（约 200 行 Python：把队列卡翻译成事件、把回执写回队列）。
- **判定**：**推荐**。

## 5. 明确不采纳

| 不采纳 | 理由 |
|---|---|
| 整体替换为 Node 栈 | 我们引擎是 Python 八态机 + 进程拓扑，换栈等于重做，且丢掉审计/写域/冻结治理 |
| 模拟小镇可视化 | 好看，对我们的监控诉求无增益；我们要的是 `status`／`why` 这类可机检输出 |
| 让 Agent 走第三方网关代挂模型 | 与我们「主脑可替换但凭据留本地」的隐私口径冲突 |
| 它的「审查独立」 | 它只有「按写代码的 Agent 指定审查」，是配置项不是制度；我们的审计独立性不能降级 |
| 直接拷它的内核代码进产品 | MIT 允许，但我们要求「新增代码模块化封装、旧版冻结」，且要过供应链审查；本稿只借机制，不拷实现 |

## 6. 风险与红线

1. **不得改 v1 冻结参数**：`config/voice-next/live.json` 一字不动（0058 已核过哈希）。
2. **不得新增产品承诺**：`unknown` 态、`hops` 上限这些是内部机制，不对用户承诺「永不丢」。
3. **写域冲突**：0057 正在写 §二十五、0059 待写 §二十六，本稿提案的 §27 必须等这两单收口后再动同一文件。
4. **许可证与供应链**：若将来真要引它的代码，需 License 审查 + 依赖锁定 + CVE 扫描（工程方法论 §10.4）。
5. **注意力纪律**：抄它的「默认安静」——没事不说话，能自己做的自己做完；这条对我们自己的派发节奏同样适用（8 个 D 项磨人那件事，就是反面样本）。

## 8. 这份方案怎么算有用

- 九个机制各能指到 0056 里至少一个缺口编号（本稿已逐条对上，8 条 BLOCKER/HIGH 被覆盖）。
- 三个形态各有明确的「拿到什么/付什么」，且推荐形态有一层 200 行以内的适配，不是概念。
- 每个拟落章节都有可机检验收锚点（能否构造负例、能否重放、能否强杀复原）。
- 不承诺任何未验证的事：Autoloop 自己的未验证项（GitLab 真实实例、ACP 多轮），本稿不当作已成立。
