# 主脑教学 Phase 2：多轮澄清（听不懂时怎么问、问几次）

- 方案版本：v1.0
- 日期：2026-11-12
- 上游：`plan-ultimaagent-mainbrain-teaching-phase1-20261112.md`（Phase 1 已冻结，tag `ultimaagent-mainbrain-teaching-phase1-20261112`）
- 范围：只做「听不懂 → 问一次 → 能接上 → 问不动就放弃」这一条闭环。不做多任务拆分、不做主动回报节奏（Phase 3）。

---

## 1. 为什么现在做

Phase 1 解决了「该动手却说做了」这一类**撒谎**问题。Phase 2 基线探针（2026-11-12，直调 `ask_once`，7 条）暴露出另一类更危险的毛病：**听不懂却装懂**。

| 探针 | 输入 | 实测结果 | 问题 |
|---|---|---|---|
| F1 | 帮我把那个弄一下 | `task` 10.71s，**直接派单** | 指代不明（"那个"）却原样派了出去 |
| F5 | 把文件发给他 | `task` 1.82s，**直接派单** | 缺对象（哪个文件、他是谁）却派单 |
| F2 | 打开 | `query` 2.68s「你是指打开设备还是应用？」 | 问了，但**无状态**，用户答了也接不上 |
| F3 | 呃那个嗯 | `query` 3.36s「你再说一遍？」 | 不是澄清，是把球踢回去 |
| F6 | 嗯 | `query` 3.57s「您再说一遍？」 | 同上 |
| F7 | 那个东西还是不行 | `query` 3.03s「你再说一遍？不清楚你指的是哪个部分。」 | 说了"不清楚"却**没给任何可选方向** |
| F4 | 帮我查一下天气然后整理桌面 | `no_tool` 0.0s，只回「查不了天气」 | 多任务只处理被拦的那半边，后半段无声消失（不在本方案，见 §7） |

**三条结论**：
1. **缺宾语/指代不明直接派单**（F1/F5）是最严重的：派出去的单子没有宾语，执行端必然空转，用户还以为安排上了。这是「装懂」，和 Phase 1 的 P1「撒谎」是同一族病的两面。
2. **没有澄清状态**：F2 问了「指设备还是应用」，用户下一句说「应用」时主脑完全接不上——全仓无会话上下文（`agent_server.py` 里的 `history` 只是 HUD 事件总线）。
3. **澄清话术不合格**：F3/F6/F7 全是「你再说一遍」，这不是澄清而是推回。真正澄清必须给出**候选方向**或**最小必填槽位**。

## 2. 事实基线（代码层，改动前）

- `agent_server.py:766-785` `_classify_intent`：只有两种出口 `task` / `query`，**没有"槽位不全"这一类**。
- `agent_server.py:788` `_ask_task_branch`：无任何前置检查，直接 `UltimaDispatchTool().execute(task=query)`（`L809`），把原话原样派出去。
- 全仓无会话状态：`ask_once` 是纯函数式单轮，`EVENT_BUS.history()` 只服务 HUD 回放。
- `_SERVILE_TAIL_PATTERN` 只剥服务性反问（"需要我帮您…吗"），**不剥"你再说一遍"**——它是推回话术，不在现有正则覆盖面内。

---

## 3. Phase 2 的定义（做完算什么样）

一句听不懂的话进来，主脑应该是：

1. **不派单**。槽位不全（缺宾语/纯指代/纯噪音）一律不进 `_ask_task_branch`。
2. **问一次，且问得出方向**。给候选或最小必填项，不是"你再说一遍"。
3. **能接上**。用户下一句补充（"就是那个报告" / "桌面的" / "应用"）能被拼回原请求继续走。
4. **问不动就放弃**。同一请求最多问 **2 次**；超时（30 秒）或问满 2 次仍不明确，明确说做不到并收起，不再追问。

## 4. 四项改动（全在代码层，不调提示词）

原则沿用 Phase 1：8B 在行为层不受提示词约束（L138），所有约束必须落成结构性代码。

### 4.1 槽位门 `_slot_gate`

新增 `_slot_gate(query) -> str | None`，返回缺失槽位的类型（`object` / `referent` / `noise`）或 `None`。

判据（正则，确定性，不调模型）：
- **`noise`**：整句实质字符极少（去掉标点空格后 < 3），或整句只由语气词构成（`嗯|呃|啊|那个|喂|在吗` 组合）。
- **`referent`**：动作存在，宾语是纯指代 —— `那个|这个|那些|这些|它|东西|那个东西`，且**没有**具体名词/路径/文件名跟随。
- **`object`**：动作存在（`_DELEGATED_ACTION_PATTERN` 命中）但**整句没有任何宾语成分**（动作词后直接结束，如「打开」「把文件发给他」中的"文件"是泛指无指定）。

> 关键：`object` 判据必须**排除**「有具体宾语」的句子。「帮我把桌面的日志整理一下」→ 宾语是「桌面的日志」，具体，不拦。只有「那个」「文件」这类泛指才拦。

### 4.2 澄清话术 `_clarify_reply`

新增 `_CLARIFY_TEMPLATES` 三类，按槽位类型出话术：

| 类型 | 话术 |
|---|---|
| `object` | 「你要我处理哪个？给我个具体名字，比如文件名或路径。」 |
| `referent` | 「你说的『那个』是指哪一个？说一下名字我就能动。」 |
| `noise` | 「没听清，再说一遍要做什么。」 |

配合新增 `_PUSHBACK_PATTERN`（`你再说一遍|您再说一遍|再说一遍|没听清`）**在 `_clean_content` 里一并剥掉**——凡模型吐出"再说一遍"类推回话术，一律替换为对应澄清模板，不留"踢回去"的出口。

### 4.3 单轮挂起状态 `_PENDING_CLARIFY`

进程内存单个字典（**不进磁盘、不跨进程**）：

```
{
  "query":   原请求,
  "slot":    缺失槽位类型,
  "asked":   已问次数,
  "at":      时间戳
}
```

`ask_once` 入口（在 `_classify_intent` **之前**）：
- 存在 pending 且 `now - at <= _CLARIFY_TTL(30s)` 且 `asked < 2` → 把新输入当**补槽内容**拼回：`f"{pending['query']}（补充：{query}）"`，清掉 pending，继续正常流程。
- 存在 pending 但超时或问满 → 清掉，回「先不弄了，需要的时候再叫我。」
- 不存在 → 正常流程。

`ask_once` 函数签名不变（`query, max_tokens=None`），状态是模块级，不影响既有调用方。

### 4.4 `ask_once` 入口顺序（改后）

```
message_in → _try_accept → _risk_gate → _no_tool_gate
          → 【新】pending 填槽（命中则合并，清状态）
          → _classify_intent
          → 【新】判 task 前跑 _slot_gate：
                有缺失 → 记 pending + 返回 clarify 话术（不派单）
                无缺失 → _ask_task_branch
```

`intent` 新增取值 `clarify`，事件总线发 `message` 事件（HUD 已有消费路径，不需要改壳）。

- 不动 provider 层 / slot_adapter / 语音链路 / GUI / installer。
- 不引新依赖（不引入会话数据库、不引入 NLP 库）。
- **不做多任务拆分**（F4 这类"查天气+整理桌面"只处理一段的问题，留 Phase 3，见 §7）。

## 8. 风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 加进程内状态破坏 `ask_once` 无状态契约，语音链路并发调用串话 | 状态是单实例模块级字典 + 30 秒 TTL + 问满 2 次即清；`ask_once` 签名不变；不落盘不跨进程 |
| R2 | 槽位门误伤正常派单（如"帮我把桌面的日志整理一下"被当成缺宾语） | 判据严格区分「具体宾语」与「泛指宾语」；反向验证 R1/R2 必须过 |
| R3 | 澄清话术又变成服务性反问（P4 复发） | 澄清模板是固定文本、不含「需要我…吗」句式；`_SERVILE_TAIL_PATTERN` 与 `_PUSHBACK_PATTERN` 双重出口拦截 |
| R4 | 用户答非所问（补槽内容本身也是模糊句）时无限套娃 | 问满 2 次强制放弃，不再追问 |
| R5 | 语音链路 `state=ready` 时批量打 `/ask` 会饿死语音（L158） | 验收一律直调 `ask_once`，不打 HTTP |
