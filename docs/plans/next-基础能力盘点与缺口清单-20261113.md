**结论（三条，写死）**：
1. B 的八块**全部有归属**：六块落「基础能力」、Update/Lifecycle 两块落「交付」——此前 T11/T12 无落点的空洞就此关闭。
2. C 不是工程模块口径，只是**功能盘点桶**，**禁止用 C 去指派代码目录**；C 的 ⑤ 是治理横切，不对应任何 B 运行时模块，属正常而非缺口。
3. 新增能力必须先定 B 落点、A 归属、C 桶，三者登记齐才算"有归属"。



#### 1.1.1 呈现层级（三类，2026-11-13 Owner 口述重组）

```
① 基础能力（六块，口径不变）
   Core / Senses.Voice / Shell / Surface / Memory / Middleware
   ＋ Console 子模块（任务调度与裁决中枢）
   ＋ 治理与约束 ⑤（横切：行为层 / 输出层 / 规则库 / 防投毒 / 审计独立 / 外发红线）
② 外部能力（容器，三抽屉）
   ├ 能力库 Skill   ：预置（随包、可停用不可卸载）＋ 扩展（用户添加）
   ├ 插件 Plugin    ：MCP / 执行端适配器 plugin.executor.<name> / provider 接入
   └ 模型库 Provider：云端 API ＋ 可选本地第二模型（**不含主脑**）
③ 交付
   Update / Lifecycle
```

**三条写死**：

1. Skill 与插件**都属外部能力**，不再是并列的一类 → 旧「五类」作废；Skill 与插件不再是第一层节点。
2. **主脑不在模型库列表、不可被 skill 指派**；但**主脑本身可替换**——配置面下拉切换（本地绿标／外部黄标），见基线 **§二十三**（R-76/R-77）。旧「不可换型」表述作废。
3. Memory 内部**三库一索引**（`mem` / `kb` / `exp` ＋ `index`），**模块数仍为六块**（「七块」说法作废）。

详见基线 **§十七（记忆三库与检索契约）/ §十八（外部能力与绑定）**。

## 二、缺口清单（按性质分五类，**共 27 项**：A 会话交互 7／B 宿主集成 6／C 可靠性 4／D 数据隐私 4／E 可观测 4／F 多用户多语言 2）

### A. 会话与交互（体验决定性，缺一项都别扭）

| # | 缺口 | 缺的是什么 | 建议 |
|---|---|---|---|
| A1 | **打断（barge-in）** | 正在播报时用户插话，是继续说完还是立刻停？没有策略 | 用户开口 300ms 内被 VAD 捕获 → 立即停 TTS，转监听 |
| A2 | **会话生命周期** | 「一次会话」从哪开始到哪结束、多久算超时、超时后回哪 | 唤醒=会话开始；**轮结束不退会话**（R-53），停在 `capturing` 继续听；**连续 60 秒无反馈**（R-55 由 5 分钟下调）才退出监听回 `ready`；单次监听上限 15s（单句，超时仍在会话内）。详见基线 §十一 |
| A3 | **多轮上下文窗口** | 保留多少轮对话进上下文，超了怎么压缩 | 保留 10 轮 / 4000 token，超出走摘要 |
| A4 | **没听清的兜底** | 连续识别失败后怎么办 | 连续 2 次 → 语音提示「没听清」；3 次 → 退出监听并回执状态 |
| A5 | **静音/勿扰** | 夜间或会议中不能出声、不该弹窗 | **归属客户端（R-49）**：引擎只提供 `dnd_state` 状态位与"静默执行"能力，**时段、开关、默认值一律由客户端定**，不进引擎（原「默认 23:00–07:00」作废） |
| A6 | **音量与语速** | TTS 音量、语速是否可调 | 音量默认 70%，语速 1.0x，可在 Console 调 |
| A7 | **主动唤出（热键）** | 不想说话时能不能按键唤起 | 默认 `Ctrl+Alt+Space`，可改 |

## 三、三个结构性缺口（不是补参数能解决的）

1. **会话（Session）没有归属**
   现在「交互循环」管的是循环本身，但"一次会话"的开始/暂停/结束/恢复没有明确归属。建议归 ①感知与交互，作为 `session` 子能力，状态落 ⑤ 的探针。

2. **打断策略不在七态状态机里**
   ~~七态有 `speaking`，但没有 `interrupted` 这第七态之外的回退路径。要么加一态，要么在 `speaking → capturing` 之间定义硬跳转。**必须先定，否则体验永远"说完才听"。**~~
   **已裁决（R-46）**：**不新增 `interrupted` 态**（加态会与全仓"七态"口径冲突，本项目 stage1 审计第 9 条即此类问题）；改为 `speaking` 上的 `barge_in_armed` 子标记 + 硬迁移边 `speaking → capturing`（`reason=barge_in`）+ **回滚闸**（未回滚禁止进 `processing`）。迁移表、参数与观测点见 `docs/specs/next-感知交互参数基线-20261113.md` **§八**。

3. **"主脑不可用"没有降级剧本**
   ~~R-29 把主脑职责压到"查/登记/汇报"，但它一挂，谁登记？建议：主脑不可用时，Console 接管登记（只登记不判断），并在四角壳明示"主脑离线，仅记录"。~~
   **已裁决（R-47）**：改为**五级梯子**（`L0 探活 → L1 诊断六类原因码 → L2 重启限次 → L3 外脑接替限授权 → L4 离线紧记录`），且**主脑不重启自己**（重启归 Shell.Guardian 宿主级执行）。外脑接替是唯一允许外发的情形，但记忆/习惯/本地文件一律不外发。全文见 `docs/specs/next-主脑不可用降级剧本-20261113.md`。
