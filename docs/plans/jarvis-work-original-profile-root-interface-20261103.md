# T4-PROFILE-ROOT-IF01 — profile consumer and later Root control boundary

The code author identified a real omission: approved T1/T5 require independent Root admission/observation but do not define the callable interface. This ruling chooses the already contemplated read-only Root verifier capability. It does not authorize a runtime, implement a controller, or change any product/SDK/harness/caller file. BOUND-01's fixed trusted-code scope applies; do not invent a cryptographic/OS confinement guarantee for arbitrary Python.

## One explicit consumer seam

In profile.py define a small `RootControls` interface with two methods:

- `admit(folder: Path, pins: Mapping) -> Mapping`: called before any selected SDK/client construction. The later reviewed enclosing Root entry supplies this capability; it reads and validates the independently Root-consumed allocation and closed entry grant, actual process creation identity, earliest clock, candidate/profile/fixture/control pins, environment/backend and scope. It returns the closed typed admission described below or raises. No default successful implementation.
- `readback(folder: Path, first: Mapping) -> Mapping`: only the independent Root reader supplies this capability. It returns independently observed process exit/identity/clock and closed-file reference evidence. It cannot take actual exit or Root observation from the worker's first-result dictionary. No default successful implementation.

`private_scope(folder,pins,admission)` may refine its admission parameter from a dict to this explicit capability/handle. A plain dict with `verified=true`, a worker-chosen record path/hash, or a worker result is never a capability. The profile is an import-only package: no public runtime CLI and no default installed Root controls. The future fixed, independently reviewed Root entry is the sole integration caller. Code preparation must not create the real capability, grant, allocation, approval, claimed worker identity or trusted-observation record. Synthetic contract tests may supply explicit doubles to test the consumer and rejection order; this proves only that consumer's contract.

The trust source is the later pinned Root entry and independent enclosing observation of its preconsumed closed records, not `isinstance`, an attribute named trusted, a secret Python token, or a hash furnished inside worker data. Do not claim the interface is unforgeable to arbitrary code. The separate Root control implementation/review must bind its exact source and record bytes, own actual allocation/identity/exit/time observation, and show that profile data cannot supply or replace them before runtime is released. A missing/unconfigured/unverified Root capability fails before SDK/client exposure. In the eventual runtime entry, no dictionary-to-capability factory may consume worker output or accept a fallback verifier.

For preparation, implement the consumer/pure shape and timing predicates and leave concrete record issuing/reading/ownership integration to that separate Root task as the approved plan already requires. This is not permission to stub the profile's factory, script, writer observation or validators. Report the external Root integration as deliberately not yet provided, not as a passing runtime.

## Closed admission returned by the capability

Use exact keys and types, rejecting unknown keys/coercion. Canonical UUID4 strings: `run_id`, `entry_nonce`. Positive true ints: `worker_pid`, `worker_creation_filetime`, `origin_ns`, `work_deadline_ns`, `cleanup_deadline_ns`, `seal_deadline_ns`. Absolute strings: `case_root`, `worker_executable`. Deadline values equal origin plus 275/310/315 billion ns, with fresh real admission before the first cutoff. Fixed strings: `candidate` = C118 full commit, `model_digest` = current8B digest, `scope` = `ORIGINAL_CORPUS_ZERO_INFERENCE_PROFILE`. True-int counts: `consumed=1`, `max_submissions=1`, `retry=0`, `actual_http_allowed=0`, `actual_11434_allowed=0`, `actual_inference_allowed=0`. `ssrf_fail_open_present` is literal false. `ssrf_backend` is the independently admitted `rust` or `python` descriptor; consumer checks the actual selected normal branch, never forces it.

SHA256 lowercase-hex fields: `profile_manifest_sha256`, `candidate_manifest_sha256`, `corpus_sha256`, `root_control_manifest_sha256`, `allocation_sha256`, `entry_grant_sha256`, `protected_before_sha256`. These values must agree with fixed inputs, actual caller/worker and the independently sealed control, not just be well-formed. The Root capability owns those comparisons; profile rechecks its own pin/clock/role fields. Later entry file/record schema and fresh byte values are the separate Root task; no selfhash or placeholder accepted as runtime evidence. Pin this ruling in the preparation manifest.

Independent readback returns exact keys `run_id`, `entry_nonce`, `worker_pid`, `worker_creation_filetime`, `python_exit_code`, `observed_at_ns`, `first_result_sha256`, `closed_index_sha256`, `expectations_sha256`, `runtime_inputs_sha256`, `protected_after_sha256`. IDs match admission, exit is externally observed true int 0 for PASS, hashes match the independently reopened closed files, and observation is on the same origin by315 seconds. Missing/not observed fields remain null and fail PASS; a worker-self-reported exit is not an observation. The reader capability must also keep raw ref/path provenance internally and check bounds/reparse/inventory and current backend/environment before selected replay calls. No new native process controller.

## Independent FixtureExpectations

Keep its data internal to profile.py with explicit fields for original ordered source URL/content-type/body/digest, original query and derived search query, live binding IDs, five preflight SDK/adapter ID pairs and producer timestamps/results, and independently captured policy/catalogue/source/page expectations. Capture the live IDs/results at their pre-composition callback boundary, alongside the already required independent RuntimeInputs capture, before collection/export serialization. Preserve a separately closed bounded observation file with its own byte hash; do not populate expected IDs/policy/pages by reopening quarantined collection/replay. Actual original inputs come from their pinned corpus, not a member being validated.

The pure collection validator may accept this typed expectations object explicitly. The independent reader obtains its reference via Root's independently reopened captured-observation evidence. It checks capture provenance/order against the fixed observer code and original inputs, reconstructs policy/catalogue/source/pages through pinned pure product routines and compares the raw members. Capture evidence, pure closed-schema validation and full typed replay/reopen are all required on unchanged bytes. Do not claim Root knew random per-call IDs before the worker generated them; independent capture before composition is the intended source. An absent or partial capture fails, never backfill from the target blob. Synthetic expectations in offline tests are labeled as such.

Why: complete the consumer interface without asking the profile author to build the later Root system or to trust worker assertions. Cost if wrong: a concrete consumer/control incompatibility must be repaired and re-reviewed before one runtime allocation; runtime and model remain closed. All original caps, source/persona/scanner/writer requirements, old failures and E02/T2/T3/Owner gates remain.
