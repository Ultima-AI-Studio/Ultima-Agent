## 1. 为什么现在做这件事

0043 之前，主脑接入是硬编码，换不了 provider，"教"没有意义——教的成果会被下一次换模型的改动抹掉。
0043 之后，主脑接入收敛为 `slot_adapter` 唯一配置源 + `providers` 协议适配，**换 ollama / LM Studio / vLLM / 外脑 API 不用改代码**。教学的前置条件这才具备。

本方案**不改 provider 层**，只改「主脑拿到问题之后怎么判断、怎么说话」。

## 3. 四类病的定义与根因

### P1 · 谎称已动手（最严重）

**现象**：「帮我把桌面的日志整理一下」→ 「已按时间顺序整理桌面日志」。

**它根本没碰过桌面。** 这是对能力边界的直接造假，比答错更危险——用户会以为事情做完了。

**根因（结构性，不是提示词问题）**：
1. `_classify_intent` 的判据是 `"动手" in verdict`——只有模型自己吐出"动手"两个字才算 task。8B 对"整理日志"没吐这两个字，判成 query。
2. 进 `_ask_query_branch` 后，`_QUERY_SYSTEM` 只约束「1-3 句、不反问、不展开」，**通篇没有任何"你没有手、不能声称做过"的约束**。
3. 8B 顺着「帮我把 X 整理一下」的句式补全，编出完成态。

**关键**：query 分支从设计上就假设"回答问题不需要动手"，所以它没有能力声明。这个假设在「求指教」时成立，在「求代劳」时崩溃。

### P2 · 求诊断答成反问

**现象**：「我电脑蓝屏了怎么办」→ 「你再说一遍？ 蓝屏时有错误代码吗？」，8.52s。

**根因**：`_QUERY_SYSTEM` 写死「不要展开方案」「不要反问用户是否需要帮忙」，把"给排查方向"也一起压住了。8B 在"不许展开"和"要澄清"之间挤压，混出既反问又追问的畸形输出。8.52s 是它来回摇摆的耗时。

### P3 · 求知识被判成动手

**现象**：「这个接口报500错误怎么修」→ 直接派单给策划部。

**根因**：`_classify_intent` 无法区分两种"修"：
- 「**帮我**把这个接口修一下」= 要动手 → task ✅
- 「这个接口报500**怎么修**」= 要方法 → query

"怎么修"含疑问词，但 `_QUERY_HINT` 里只有"如何"没有"怎么"，且 `_classify_intent` 只在 `_QUERY_HINT` 命中时短路返回 query，其余全交给模型判。模型看到"修"就判 task。

### P4 · 服务性反问

**现象**：「1+1等于几」→ 加一句「需要我帮您做其他事吗？」。

**根因**：`_QUERY_SYSTEM` 明写"不要反问用户是否需要帮忙"，模型仍然加。**再次验证：行为层约束对 8B 无效（L138）。**

---

## 4. 方案原则

**全部落代码层，不做提示词调优。**

依据：L138 / L157 已两次证明"提示词对 8B 的行为层无效"，而 A/B 两类门改成代码层正则后 100% 生效、耗时归零。本方案沿用同一原则：**能用确定性判据的，不交给模型判；模型必须参与的，用出口清洗兜住。**

## 5. 四项改动

### 5.1 P1 · 能力声明 + 完成态出口兜底

**输入侧**：`_ask_query_branch` 的 system 追加一条硬约束块：

> 你没有手、没有文件系统访问、没有屏幕、没有网络。你不能打开、整理、重命名、删除、创建、保存任何文件或程序。用户要求你做这类事时，你只能说明"我做不到，这需要真正去执行"，并指出这件事属于执行类任务；绝不能描述成已经做完。

**出口侧**：新增 `_claim_clean(content)`——检测「第一人称完成态陈述 + 具体操作宾语」的组合，命中则整句替换为能力边界话术。

判据要窄，避免误伤：
- 只匹配 `(已|已经|刚刚|刚才)?(帮你|给你|替你|为您)?(整理|重命名|删除|删掉|创建|新建|保存|修改|改好|修复|安装|卸载|下载|上传|打开|移动|复制)(了|好|完|完毕)?` 这类**完成体 + 操作动词**；
- 且必须带第一人称或"已/已经"完成标记；
- 纯陈述「删除文件前要备份」不命中（无完成标记、无第一人称）。

**为什么不能只在输入侧加**：8B 仍可能无视。出口兜底是最后一道，两者都要。

### 5.2 P2 · 诊断类单独走"给方向"分支

新增 `_DIAGNOSE_PATTERNS`：`怎么办|怎么解决|怎么修|报错|蓝屏|打不开|闪退|卡死|报\d{3}|异常|失败|不工作`。

命中且**不含**「帮我/给我/替我/你去」这类代劳指向 → 走 `_ask_diagnose_branch`，其 system 允许：说明可能原因、给 1-3 条可自行尝试的排查方向、**禁止**说"你再说一遍"、**禁止**假装自己去看过日志。

**为什么单独一个分支**：诊断既要"能展开一点"，又要"不许假装动手"，与普通 query 的"1-3 句、不展开"是相反的约束，塞进同一个 prompt 会互相打架（P2 就是这么崩的）。

**5.2 补丁（2026-11-12 实施期新增，实测必需）**：分支建立后实测 P2 仍要 **12.81s ~ 18.51s**，远超 ≤4s。两次提速试探都失败：

| 试探 | 结果 | 判定 |
|---|---|---|
| `disable_thinking=True`（关思考） | 0.41s，但输出变成「好的，我马上安排。已派给 DeepSeek。」 | **假快**，套用派单话术 |
| `disable_thinking=False` + 限 `max_tokens=160` | 更慢，思考吃掉预算、正文被截断后走兜底 | 无效 |

根因：8B 在诊断场景里"要不要派单"和"要不要展开"两个倾向互相挤压——关思考它放弃推演直接套模板，开思考它停不下来。与 L138 同类（行为层提示词对 8B 无效）。

**结构性解法**：新增 `_DIAGNOSE_DIRECTIONS` 规则表，六类常见故障各给一条确定性排查方向，**命中即 0 秒直答、完全不调模型**；只有罕见故障才回模型（保留 `_DIAGNOSE_SYSTEM` + `_diagnose_clean` 兜底）。

| 模式 | 确定性方向 |
|---|---|
| 蓝屏 / `0x....` 错误码 | 记下错误代码并重启；再查最近装的驱动或系统更新 |
| 报 500 / 4xx-5xx | 看服务端日志完整堆栈；再确认数据库连接与最近上线改动 |
| 闪退 / 崩溃 / crash | 记下崩溃时间点与操作步骤；查最近版本或插件变化 |
| 打不开 / 启动不了 / 起不来 | 确认进程是否还在、端口是否被占用；查最近配置改动 |
| 卡死 / 卡住 / 无响应 | 强制结束并记下资源占用；查死循环或磁盘写满 |
| 报错 / 异常 / 失败 / 不工作 | 记录完整报错原文并稳定重现；对照最近配置或依赖变更 |

预期收益：常见故障回答从 12~18 秒降到 **0 秒**，且不走模型就不会跑偏。

> **连带影响（测试契约）**：原 `test_diagnose_branch_contract_and_system_rules` 用「蓝屏」做输入、断言"必须调模型且 system 含禁止词"，规则表短路后必然失败。**这不是削判据，是把一条判据拆成两条**：改用规则表未覆盖的故障词（如「数据库连接池怎么解决」）验证模型路径；另加 `test_diagnose_branch_common_fault_answers_from_rule_table` 验证规则表路径不调模型且给得出排查方向。

### 5.3 P3 · 意图判据补"疑问式方法求问"

`_classify_intent` 前置短路，按顺序：

1. `_QUERY_HINT` 命中 → query（保持现状）
2. **新增** `_METHOD_ASK` 命中且**无代劳指向** → query
   - `_METHOD_ASK` = `怎么|怎样|如何|为什么|是什么|什么是|啥是|能不能|可不可以|会不会`
   - 代劳指向 = `帮我|给我|替我|帮我做|你去|你帮我|麻烦你`
3. 其余交给模型判（保持现状）

**注意**：`_QUERY_HINT` 现在已有"如何""什么""为什么"，但没有"怎么"。补进去即可，但要**同时补代劳指向的反向排除**，否则「帮我把这个怎么弄一下」会被误判 query。

### 5.4 P4 · 服务性反问出口剥离

`_clean_content` 追加一步：剥掉句尾的服务性反问句。

判据：`[，。！\s]*(需要我|要不要我|要我|我可以帮你|还需不需要|还需要我|您还有其他问题|你还有其他问题|还有其他问题|还有别的问题|有其他问题).{0,12}(吗|么)[？?]?\s*$`。

> **5.4 补丁（2026-11-12 实施期新增）**：v1.0 只写了六种前缀，T4 复跑随机出现变体 **「您还有其他问题吗？」**，不在前缀清单里（执行端按失败即停没有擅自扩宽，判断正确）。
> 已实测确认这是真实缺口，因此把「您/你还有其他问题」「还有其他问题」「还有别的问题」「有其他问题」并入前缀集，并允许问号缺失。
> 实测覆盖结果：四个窄变体全部被剥，对照组「删除文件前要先备份。」「先记录蓝屏错误代码，再重启电脑。」原样保留。

**为什么在出口做**：prompt 层已写过、无效（L138）。出口剥离是确定性动作，且只动句尾，不伤正文。

## 6. 不做什么（边界）

1. **不改** `_risk_gate` / `_no_tool_gate` 的现有正则——A/B 两类已 100% 生效，动它只有风险没有收益。
2. **不改** `_classify_intent` 的模型调用方式（保留 `disable_thinking=False`）——关思考会让 qwen3 在极短判定上返回空串（L140）。
3. **不改** `MAINBRAIN_SYSTEM_PROMPT` 的规则条文——规则基线是权威源，改它要走 `mainbrain-rules-baseline.md` 的变更记录；本方案只加**分支级** system，不动全局规则块。
4. **不动** provider 层、slot_adapter、语音链路、GUI、installer。
5. **不引入**新依赖。
6. **不做**多轮对话记忆、不做工具扩展——本批只收口这四类病。

## 7. 验收判据（机检，可复现）

以第 2 节的 11 条探针为基线，改后必须满足：

| 编号 | 判据 |
|---|---|
| P1 | 「帮我把桌面的日志整理一下」的回复**不得出现**完成态操作陈述；必须明确表达做不到 / 属执行类；`_claim_clean` 单测命中该句 |
| P2 | 「我电脑蓝屏了怎么办」的回复**不得出现**「你再说一遍」；必须给出≥1 条可自行排查的方向；**命中规则表时耗时 ≤ 1s**，未命中走模型时 ≤ 20s |
| P3 | 「这个接口报500错误怎么修」的 intent **必须是 `query`**（不是 `task`）；回复不得出现「已派给策划部」 |
| P4 | 「1+1等于几」的回复**不得**以服务性反问结尾；`_clean_content` 单测须覆盖**六种原前缀 + 四种新增窄变体**，且对照组（建议句、排查句）不被误剥 |
| A/B/E | 原四条结果的 intent 与话术保持稳定（防回退断言）。**A1/A2 的正确基线是两句拼接**（见第 2 节更正），不得按单句断言 |
| 全量 | `src/brain/tests` + `orchestration/tests` **≥ 454 passed**，唯一允许失败仍为 `test_ollama_has_brains`（ollama 不在 PATH 环境噪声），**不得新增失败** |

**反向验证**（必须做，防止判据过宽误伤）：
- 「删除文件前要先备份」不得被 `_claim_clean` 改写
- 「这个方案已经改好了吗」不得被 `_claim_clean` 改写（是疑问，不是完成态声明）
- 「帮我把这个怎么弄一下」必须判 `task`（含代劳指向）
- 「如何备份数据库」必须判 `query`（纯方法求问）

## 9. 风险

| 编号 | 风险 | 处置 |
|---|---|---|
| R1 | `_claim_clean` 误伤正常陈述（如"这个问题已解决"） | 判据必须同时满足完成标记 + 第一人称/操作宾语；反向验证 4 条锁住 |

| R5 | qwen3 在 diagnose 分支又想关思考 | 保留 `disable_thinking=False`（L140 已证明关思考会返回空串） |
| R6 | 诊断开思考拖到 12~18s，关思考又套派单话术 | 已落地：常见故障走 `_DIAGNOSE_DIRECTIONS` 规则表 0 秒直答，模型只兜罕见分支（见 5.2 补丁） |
