# HUD Windows 桌面交互方案 hud-windows-window-interaction-plan-20261031

> 版本：v0.5（v0.4 基础 + 待澄清项登记）｜ 状态：Owner 拍板定稿（含待澄清 5 项）｜ 日期：2026-10-31
> 依据：Owner 讨论（2026-10-31）：**Windows 桌面环境下 HUD = 普通可拖动窗口，不做穿透点击；默认不置顶可被其它窗口覆盖，置顶为显式按钮；锚位=无边框气泡形态，固定才显边框；右上角=语音切换单功能窗口；消息=气泡上顶消失；穿透/透传是 AR 环境逻辑**
> 关联：`docs/previews/hud-layout-zone-plan-20261031.md`（8 锚点布局 v0.2 定稿）、工单 0011、`docs/previews/hologram-avatar-plan-20261031.md`

---

## 一、核心结论（Owner 拍板）

**Windows 桌面环境**：HUD 窗口 = **普通可拖动窗口**。
- 鼠标在窗口上 = 操作这个窗口（锚位可点、可拖动、可交互）；
- 想操作窗口下面的桌面图标 / Windows 功能 = **把窗口拖走**；
- **不做穿透点击逻辑**（窗口不穿透到下方区域）。

**AR 环境**：才是透传 HUD 逻辑（现实空间非鼠标操作，HUD 为视野叠加，天然不冲突、不需穿透开关）。

**两套环境两套交互逻辑，不混用。**

---

## 二、为什么之前的方向不对（纠正记录）

v0.1（`docs/plans/hud-clickthrough-zone-plan-20261031.md`）曾提出"区域级 WM_NCHITTEST 局部穿透"（8 锚位可点 + 中央透传点桌面）。**已废弃**——理由（Owner 拍板）：
1. Windows 桌面交互直觉是"窗口即操作面，拖走才能点下面"，穿透点击反而违背常规窗口心智；
2. 局部穿透需要维护区域表、处理锚位显隐增量更新，复杂度高且收益为负；
3. 穿透逻辑只在 AR/沉浸式场景有意义，不应带入 Windows 窗口。

> 废弃文档保留为历史参考（904311a），以本文档 v0.2 为准。

## 三、Windows 窗口交互设计（定稿）

| 项 | 行为 |
|---|---|
| 窗口形态 | 分层透明窗口（视觉上仅见锚位壳内容），**可整体拖动** |
| 鼠标在锚位区 | 正常交互：点击天气/消息/任务队列/反馈区等 |
| 鼠标在窗口空白/透明区 | 属窗口本体——不穿透；但**拖动窗口**即移开（拖动手柄/锚位壳任意处） |
| 想操作下方桌面 | 把窗口拖走（拖动到屏幕其他位置/边缘），下方即露出可操作 |
| **置顶策略** | **默认不置顶**——其它普通窗口可正常覆盖四角壳；每个视角窗口提供**置顶小按钮**（对应最早 Agent 方案功能），点击后该窗口置顶（Topmost），再点取消；托盘同步提供"窗口置顶"菜单项 |
| 与 8 锚点布局关系 | 布局仍为 8 锚位（统一范式），窗口可整体移位；无任务/静默时锚位自动隐去，窗口自然"变空"不挡视线 |
| **形态（无边框气泡）** | 锚位默认**非卡片**：无边框、气泡/浮窗感（轻量悬浮、半透明、无描边卡片）；**固定才显示边框**，取消固定恢复气泡态（对应布局方案 v0.3 设计原则 12/14） |
| **右上角单功能切换** | 右上角**不堆叠全部功能**，语音切换单一功能窗口：默认天气→切导航变导航态；或导航时天气缩为顶部迷你态（对应布局方案 v0.3 设计原则 13） |
| **消息气泡上顶消失** | 即时通讯/简讯消息以气泡队列呈现：一条条从下往上顶→展示→消失，非固定卡片列表 |
| 托盘总控 | 保留窗口显隐（显示/隐藏）开关；不再有"穿透"开关（Windows 场景无此概念） |

**AR 场景（后续）**：四角壳贴视野边缘 + 透传 + 透明度三档 0.14/0.55/0.85 + 中央永远透传（沿用 `hud-layout-zone-plan-20261031.md` AR 安全基线），交互由视线/手势/语音承担，与 Windows 窗口逻辑独立。

## 四、改动范围与边界

**写域**：
- `src/host-shell/UltimaAgent.Hud/HudWindow.xaml`（**去掉硬编码 Topmost="True"**，默认不置顶）
- `src/host-shell/UltimaAgent.Hud/HudWindow.xaml.cs`（窗口拖动交互、透明区不穿透、托盘显隐、**置顶切换 SetTopmost(bool)**）
- `src/host-shell/UltimaAgent.Hud/TrayManager.cs`（穿透开关→显隐开关语义，**新增"窗口置顶"菜单项**）
- `src/host-shell/UltimaAgent.Hud/Native.cs`（如需：去除 WS_EX_TRANSPARENT 依赖/仅保留 AR 模式预留）
- HUD HTML 侧：锚位内容与交互、**每个视角窗口的置顶小按钮**（hud-live-four-corner.html，0011 改造后接入）

**禁止**：不动 Manager 内核 / agent_server 结构路由 / 8 锚点布局结构 / 全息人物资产。

**依赖**：前置=工单 0011（8 锚点布局改造）验收通过——0011 禁项=不动原生壳，本工单写域在原生壳，二者串行。

## 七、待澄清项（方案审视 2026-10-31，主脑提出待 Owner 拍板）

> 以下为对 v0.3/v0.4 定稿的批判性审视，非定稿变更；拍板后并入正文。

| # | 问题 | 影响 | 候选方案 |
|---|---|---|---|
| ① | **窗口粒度结构性矛盾**：现状原生壳=全屏 Maximized 透明窗；"普通可拖动/拖走才能点下面/每视角窗口置顶按钮/右上单功能窗口"均指向锚位独立小窗 | 全屏窗物理上拖不走，与"无穿透+拖走"直接冲突 | **8 锚位独立无边框小窗**（各自可拖、各自置顶按钮；中央天然透传、任务栏永不被挡）vs 边缘壳非全屏单窗 |
| ② | **天气双驻位**：顶部=时间+天气 且 右上默认=天气 | 同一信息两处常驻，重复显示 | 右上=单功能主位（默认天气）+ 顶部=时间（导航时承接天气缩略）；或顶部常驻天气、右上默认空白 |
| ③ | **消息上顶无边界**：右下气泡一条条上顶 | 顶入右中/右上区域，跨区视觉冲突 | 定义顶出上限：右下区内有限队列高度，超出整体淡出，不跨区 |
| ④ | **"固定" vs "置顶" 语义**：固定=显示边框（pin）、置顶=不被覆盖（topmost） | 两概念易混，实现联动不明 | 明确：固定是否连带置顶；或固定=纯视觉边框，置顶独立 |
| ⑤ | **置顶按钮显隐**：气泡态默认无边框，按钮常显破坏极简 | 8 锚位常显 8 个按钮视觉噪音 | hover/固定态才出现按钮 |
