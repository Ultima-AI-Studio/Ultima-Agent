三类总图

02

基础能力内部 · 六块

参数取自已冻结规格；待定项须在对应工单派发前定案

Core · 理解与裁决

听懂 → 决策 → 路由 → 复述确认；记忆写入的唯一裁决者

intent_router / planner / confirm_gate / memory_boundary
已定：意图分级 L0>L1>L2>L3 ｜ 路由 config/interface-routing.json（schema v2）｜ 复述确认双通道 ｜ 主脑不可用五级降级

Senses.Voice · 语音进出

唤醒 → 收声 → 识别 → 合成；会话不因一轮结束而中断

kws_backend / vad_tail / asr_pipeline / tts_cv3 / session_loop
已定：唤醒词「幂幂」threshold 0.30（v1 仍 0.25 冻结）｜ 七态状态机 ｜ 会话保持：轮结束停 capturing，60 秒无反馈才退监听

Shell · 进程治理

唯一允许「起进程、管进程、收进程」的地方；启停意图由 Console 下达

host_shell / guardian / job_manager / child_supervisor / autostart_entry
已定：Guardian 20s 探活 / 3 次失败 / 300s 冷却 ｜ 探活端口 8756 ｜ 必遍历 config/host-tasks.json

Surface · 界面与呈现

只画、不管：呈现内容与时机由 Console 定；四角壳 8 锚点是唯一显示形态

hud_shell / anchor_renderer / task_manager_panel / webview_bridge
已定：锚位宽度 clamp(280px,24vw,352px) ｜ 常驻仅顶／左上／右上 ｜ 中央零遮挡 ｜ 任务管理器面板 960×640

Memory · 记忆与自学习

三库一索引；写入由 Core 裁决，检索按库分开

writer / poison_guard / store_backend / temperature_tier
已定：mem / kb / exp ＋ index 横切 ｜ top_k=5 ｜ 热/温/冷三层 ＋ 存储卷可扩 ｜ 模块数仍六块

Middleware · 执行端与票据

执行端可替换、一次一主、票据可追；八态定义权在此层（不是 Console）

queue_engine / state_machine / router / delegation / task_window / ticket / sandbox
已定：八态 QUEUED→EXECUTING→SELF_CHECK→AUDIT→COMPLETED（＋FAILED/BLOCKED/CANCELLED）｜ COMPLETED 必须 audit_passed
④ 宿主与编排中的 Console

Console ＝ 引擎中心管理调度器（Engine Central Scheduler）

任务编排派发 / 优先级 / 依赖
常驻托管看谁在跑、跑多久
输出呈现把状态递给 Surface
多端调度投递给用户设备 / 显示端

边界（可机检）：代码只要会碰进程 / 网络 / 磁盘 / 像素，就不属于 Console。Console 若自己 CreateProcess 起看门狗，就成了第二个父进程 → 孤儿进程复发。进程留在客户端域是刻意选择。八态只读写、不定义（定义在 queue_engine.state_machine）；看门狗只看「起 / 停 / 查」意图，进程由 Shell 起。

⑤ 治理与约束 · 横切（不占运行时模块）

不属于六块中的任何一块，也不单独成块；对所有模块施加约束，自身不执行业务动作。五条行为学原则在这一层，不是引擎下的并列分支（基线 §二十 · R-67）。

行为层 · 五条行为学原则（软约束）感官分工理解先于行动复述确认记忆分层不打扰与反馈闭环输出层约束规则库（带版本与生效范围）防投毒审计独立（谁开发谁不自审）外发红线

四类不许顶替：行为层（软约束，用户不可改，改动走 §六 变更流程）／不变式（代码断言，不入库）／可配策略（规则库，带版本与生效范围）／红线（防投毒·审计独立·公有云盘禁作冷层）。

03

Memory 内部 · 三库一索引

三个检索入口分开，不做混检
mem
用户记忆：偏好、习惯、事实；写入由 Core 裁决
kb
知识库：书架＝领域 / 书＝来源单元（带来源＋许可） / 页＝最小检索单元；初始为空，指令驱动采集
exp
经验库：踩坑记录；draft → 人工 confirmed 才可作决策依据，未确认不得引用
index
索引横切：语义分块＋10–15% 重叠、必带位置、FTS5＋向量 RRF、top_k=5、增量优先
存储形态：store/ 分库分层分片（每库 hot.db / warm.db / cold/*.dbx，kb 一个书架一个子库）；正文只搬一次，索引只存指针 (volume, file, offset, len)；容量按存储卷扩——盘满挂新盘、可接私有 NAS，无全局硬门。
04

外部能力 · 三抽屉

能力可加、可指派；能力×模型一对一

能力库 Skill

产品策划、代码开发、方案撰写、代码审计、知识采集、顾问咨询。界面上是卡片：是否添加成功 ＋ 指派下拉 ＋ 状态灯。

skill.plan.* ／ skill.code.* ／ skill.kb.collect.*

插件 Plugin

接线层：provider 适配、执行端适配（plugin.executor.<name>）、MCP 客户端、采集浏览器档、存储后端。

plugin.provider.<name> ／ plugin.mcp.<name>

模型库 Provider

已配置好的云端大模型 API 列表 ＋ 可选本地第二模型；换绑＝在列表里手动下拉，即时生效，在途任务等本轮结束。

六态：ok ／ no_token ／ auth_failed ／ unreachable ／ rate_limited ／ disabled

预置 vs 扩展：预置能力随安装包自带（出场即激活、可停用不可卸载）；扩展能力由用户添加（可删）。
主脑不在模型库：内置 local.llama，127.0.0.1:11435，受基线 §十六 管，不可指派、不可换型。
05

谁对谁做什么

箭头方向＝依赖方向
关系类型说明
Core → Memory写入裁决记忆写入的唯一入口；越权写入直接拒绝（memory_boundary）
Memory → Core检索供给查回 kb / exp 作「软参考」；低于阈值返回「没找到」，禁硬凑
Console → Middleware派发Console 决定「做什么、先做谁」，Middleware 负责「跑起来、留票据」
Middleware → 外部能力调用按能力×模型绑定选 provider；一对一，无主备、不自动切换
Shell → 全部进程托管Job 托管、子进程回收、Guardian 探活；只有 Shell 能起进程
Console → Surface呈现只递状态给 Surface 画；Surface 不回写状态
⑤ 治理 → 全部横切约束不变式是代码断言（不入库），可配策略进规则库（带版本与生效范围）；规则库不归记忆
交付 → 全部打包/更新Update 管通道与签名，Lifecycle 管安装/升级/卸载；shipped_tasks=[] 唯一权威声明
06

六条最容易画错的关系

每条都对应一处已发生过或已预判的破防
Console 不碰进程自己起进程＝第二个父进程，孤儿看门狗复发，生命周期闸1 破防
主脑不进模型库进库就能被指派 / 换型，§十六 那套运行契约就形同虚设
Provider 不自动换绑降级只改档位与退避，不替用户改配置
规则库不归记忆记忆是被检索的软参考，规则是被执行器强制的硬门，混放会「提示词化」
Skill / 插件不是第一层它们属外部能力容器；再并列一次就回到五类
Console 不等于「终端」以外的意思「终端」此后只指 Console，不指执行端 / 用户设备 / 显示端
