## 1. 本次交付目标

用户用自然语言提出电脑工作任务，Ultima 能识别工作对象、调用实际工具、连续处理必要步骤、检查结果，并交付文件或明确的工作成果。用户可以继续上一任务；失败、取消和恢复必须反映真实状态。

KWS 按用户确认的可用状态保留。本次不重新选择唤醒引擎，不把语音音色、远场指标或主动唤醒研究作为架构交付的前置条件。

首版收口为三类工作：资料整理与本地文件交付、当前工作对象的摘要或改写、同一任务的连续修改。任务恢复、明确偏好记忆和真实进度为这三类工作的配套要求。

## 2. 架构约束

| 编号 | 必须满足的行为 |
|---|---|
| R01 | 文字和语音的工作请求进入同一个任务服务；本地或云端模型的选择不改变工具授权、执行和结果核验路径。 |
| R02 | 复用现有 OpenJarvis ReAct、ToolRegistry、ToolResult、会话存储和 Ultima 编排/执行通道。新代码集中在接入、平台适配和结果核验，不另造完整 Agent 框架。 |
| R03 | 每个请求能关联 request_id、session_id、task_id、实际工具调用和交付物；HTTP 成功、工具成功、任务目标达成分别记录。 |
| R04 | 当前窗口、选区、文件和页面上下文带来源与采集时间；修改前检查目标仍然有效。文档内容是数据，用户操作要求保留为指令。 |
| R05 | 文件任务必须经过实际写入和独立读回才能报告完成；证据至少含绝对路径、内容校验、工具结果和最终任务状态。 |
| R06 | 会话历史、当前任务与交付物关联、明确偏好分别管理；跨会话隔离，记忆写入经过现有过滤门。 |
| R07 | 失败不能自动变成“完成”；取消后旧结果不能覆盖新任务；写入重试和进程恢复不能重复产生副作用。 |
| R08 | KWS 运行基线和固定唤醒词保留；不改全局队列、真实记忆或无关应用来制造验收结果。 |

写域由用户工作要求与产品授权确定并绑定请求；模型生成的工具参数只能在该写域内选择目标，不能自行扩大写域。

以下为实施默认建议，T0 评审时固定：沿用当前主脑与已安装执行栈；模型或依赖升级另行说明必要性；默认只采集用户请求所指的当前窗口；先做文字完整链路，最终通过同一任务服务接回语音。

## 3. 固定工作任务

所有样本在实施前写入固定夹具。自由文本按事实、引用和任务结果判定，允许措辞变化；禁止以模型自评置信度或固定回复字符串替代成果检查。

| 用例 | 用户任务与输入 | 通过条件 | 归属 |
|---|---|---|---|
| E01 | 将固定三条材料整理为摘要，保存到本轮指定目录 | 三条事实均保留、无新增事实；真实文件存在；读回内容与交付说明一致；有可打开的绝对路径 | R01/R02/R03/R05；T1 |
| E02 | 查询一个固定主题的公开资料，整理带来源文档 | 受控资料集回放可重复通过；另做一次真实联网流程并检查至少三条去重来源、引用对应事实和本地文件。离线回放不能替代联网验收 | R01/R02/R05；T2 |
| E03 | 在专用测试窗口选中一段文字，要求摘要或改写 | 实际取得目标窗口与选区；内容对应选区；只修改批准的测试目标；焦点或选区改变时重新观察或明确停止 | R04/R05/R08；T2 |
| E04 | 接着说“刚才那份文档补一段结论” | 同一会话定位原交付物并修改；其他会话不串入；多候选或目标丢失时明确呈现歧义，不修改任意文件 | R03/R04/R06；T3 |
| E05 | 明确要求记住一个格式偏好，另起会话继续工作 | 偏好在新会话生效；合成密钥/外部指令样本不进入长期偏好；验证使用隔离存储 | R06；T3 |
| E06 | 工具读写失败、网络不可用或核验不通过 | 有可定位的失败步骤；不报告完成；只对适合重试的操作做有界重试；保留已确认成果；恢复后重新核验 | R03/R05/R07；T4 |
| E07 | 执行中取消、响应丢失重试、在写入边界重启测试工作进程 | 取消已确认后不再提交新副作用；已提交写入如实登记；旧结果不污染新任务；同一请求不重复追加或覆盖。无法证明安全恢复时停在需处理状态 | R03/R07/R08；T4 |
| E08 | 从产品文字入口和现有语音入口完成同类文件任务 | 两种入口使用同一任务服务和证据口径；语音由用户现场体验确认；进度、成果路径、失败原因在产品中可见；KWS 基线无未批准变化 | R01/R03/R08；T5 |

每个技术阶段运行本阶段用例和已通过的前序用例。核心模型任务在同一候选版本连续通过三轮，保留全部结果；任一失败不得只挑选成功记录。三轮通过表示该固定样本集合通过，不是开放任务的成功率承诺。

## 4. 交付证据与退出条件

每次运行保存在 `data/evidence/jarvis-work-capability/<run_id>/`，至少包含：

- `receipt.json`：契约修订与哈希、代码 commit、测试环境、模型/工具配置、用例结果、失败项和产出路径。
- `trace.jsonl`：任务状态、真实工具开始/结束、取消及核验事件；敏感内容按现有规则处理。
- `artifacts.json`：文件路径、SHA256、读回结果及其关联的工具调用；窗口任务记录操作前后观察结果。
- `test-results.xml`：本次测试结果；人工体验单独记 `owner-acceptance.md`，不由程序预填 PASS。

T1—T4 技术通过需独立审查和出口证据。进入下一阶段前，前阶段必需用例全部通过且来源未变化。缺依赖、真实服务或现场体验时如实记录等待项，不以模拟结果充当真实验收。

最终交付需要 E01—E08 全部满足、Owner 验收、候选版本及依赖清单、启动说明、已知限制、回滚方法和远端可解析的冻结 tag。技术 PASS、文档完成和实际冻结分别记录，发布继续遵守现有独立发布门。

## 5. 防止目标偏移

唯一追踪链为：`R 编号 → E 用例 → 本次 T 阶段 → 工单写域 → 代码变更 → 新鲜运行证据 → 验收 commit/tag`。每项代码变更必须能解释为满足某个用例或修复该用例所需的前置问题。

变更验收条件、任务种类、写域、开源底座或模型策略时，增加契约修订并说明原因、影响和补充验证；旧结果保留并标记适用版本。禁止降低验收要求来消除失败，禁止用新标题或新工单清空失败历史。

本次暂缓：后台持续截图、主动提醒、全新 UI、跨设备同步、自动记忆自学习、重新调参 KWS、无具体工作任务支撑的大规模工具扩张。遇到阻塞当前用例的问题，只纳入最小必要修复。
