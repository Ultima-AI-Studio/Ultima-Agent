# 工单命名与卡片路径契约

## 目标

全系统只使用一套工单号语法和一套工单卡解析规则。唯一权威实现在
`scripts/order_naming.py`；其他代码、测试和文档不得复制或另行定义工单号正则。

## 工单号语法

工单号必须满足以下全部条件：

- 以小写 `wo-` 开头；
- 前缀后至少有一个由小写英文字母或数字组成的非空段；
- 后续段使用单个连字符分隔，每段仍须至少含一个小写英文字母或数字；
- 不允许大写字母、下划线、空格、连续连字符或尾随连字符。

合法例子：

- `wo-orb-w1`
- `wo-s1-host-shell`
- `wo-agent-audit-s1`
- `wo-s7-memory-temperature`
- `wo-ultimaagent-20261108-0030`

非法例子：

- `wo-`
- `WO-S1-X`
- `wo_s1_x`
- `wo s1 x`
- `wo-s1-`
- `wo--s1`

## 工单卡落盘形式

给定工单号 `<order>`，`tasks/queue` 下只允许以下两种对应形式：

- `<order>.md`
- `<order>--<slug>.md`

`<slug>` 是非空的人类可读文件名后缀，不属于工单号。解析时必须只匹配上述精确
形式，不能把共享前缀的另一个工单当成本工单。实际命中 0 张或多于 1 张卡时均须
失败，并在错误中列出实际命中；调用方不得猜测或自行选择。

## 单源约束

`scripts/order_naming.py` 是命名语法与卡片路径解析的唯一权威。所有派发、验证、
审计、冻结和测试消费点都必须导入该模块的公开接口；禁止在其他位置写第二份工单
号正则，禁止自行拼接 `tasks/queue/<order>.md`，也禁止用更宽松的局部规则绕过契约。
