# Ultima 工程铁律清单（Ultima Engineering Laws）

> 版本：v1.0 ｜ 生效：2026-11-01（用户明确拍板）｜ 适用范围：Ultima 全系产品及全部产出型任务（豆包主脑直做 / Codex 派发 / 其他执行端一律适用）
> 定位：跨项目硬约束清单。开工前必须满足"准入闸门（DoR）"，交付必须满足"验收闸门（Gate）"；两条闸门以本清单为判据。
> 关联：`Codex-外部执行端调用范式.md`（执行适配器细则，DoR 六项定义）｜ `UltimaAI-任务工作流范式.md`（G-TASKFLOW-001）｜ `_shared\templates\工单模板.md`（任务卡模板）
> 唯一权威源：`H:\UltimaAI\_shared\paradigms\Ultima-工程铁律清单.md`（镜像：ultima-docs-repo `docs/shared/`）

## 0. 一句话总纲

**能用开源，绝不自研；所有开发默认用现成开源代码拼装。** 自研是例外不是默认——每张工单在开工前必须证明"没有可用的现成方案"，拿不出证明就不许写自研代码。

## 1. 铁律 G-OSS-001｜开源优先硬边界（2026-11-01 用户明确要求，全系强制）

1. 所有开发默认采用现成开源组件拼装；能用开源绝不自研。
2. **开工前（DoR 第六项）**：每张工单必须附"开源替代排查"结论——列出排查过的现成开源件（名称 / 版本 / 是否可用）及采用或放弃的理由；**未附结论 = DoR 不满足，禁止派发、禁止开工**（豆包直做任务同样适用：动手前先查现成件）。
3. **验收（Gate）**：凡自研或自写模块，交付必须附"为何不用现成库"说明（一句话即可，但必须写）；答不上来 = Gate 不通过，打回。
4. **反例清单（已登记踩坑，禁止重蹈）**：KWS 唤醒自训发音变体（现成：Porcupine / sherpa-onnx KWS）｜断句自写固定静音逻辑（现成：silero-vad）｜流式自拼双线程（现成：sherpa-onnx 真流式）｜AEC / 降噪 / 增益自研（现成：WebRTC AudioProcessing AEC3 / RNNoise / DeepFilterNet）。这些领域禁止再从零写算法。
5. **例外仅两类**：① 产品差异化内核（编排 / 记忆 / 行为 / UI 体验层，北极星贾维斯所在）；② 现成方案经排查确认不可用（许可 / 性能 / 平台 / 离线约束），且结论已写入工单。

## 2. 铁律 G-OWF-001｜工单三段式 + DoR 六项

1. 工单必须"三段式"：**文件**精确到路径 / **写什么**逐条可执行编号 / **验收**封闭清单全绿才过 / **禁止**明确不做什么。
2. 派发必须 DoR **六项全绿**（见 Codex-外部执行端调用范式 §4）：
   1. 验收 Gate 可判定（固定输入 / 唯一期望 / 证据位置）
   2. 无未决依赖（前置冻结 tag 存在）
   3. 写入域已声明（各 T 精确到文件路径）
   4. 推理强度已声明（high / medium / low）
   5. 禁止项已写（每条 T 有明确禁止清单）
   6. **开源替代排查已附（G-OSS-001，2026-11-01 新增）**

## 3. 铁律 G-DISPATCH-001｜全局登记 + Manager 刷新

1. 派发前必须先在全局主表登记（项目 / 工单 / 状态三要素），禁止绕过全局登记直接派 Codex。
2. 登记后必须触发一次 Manager 权威刷新（RuntimeAuthority.refresh），只登记不刷新 = 登记未闭环。

## 4. 铁律 G-WIP-001｜WIP 双层上限

每项目执行中 ≤1（同项目不并发）+ 全项目执行中进程 ≤3；审计中 ≤1；一单一进程，禁止一包多单。

## 5. 铁律 G-FREEZE-001｜冻结门 + 打 tag

1. 未冻结不进下一阶段；阶段报告缺失 / 冻结 tag 缺失 = 冻结门未闭合。
2. **关键修改 = 改了核心代码 / 配置 / 队列 / 范式 / 数据结构，或涉及版本 / 接口 / 冻结边界的任何改动**——完成即自动打 tag（`git tag <节点> && git push --tags`），无需逐次询问；先打 tag 再宣称完成，缺 tag = 闭环未完成。

## 6. 铁律 G-RECEIPT-001｜回执必报

回执必报字段：链路号 / 执行端 / 完成状态 / 根因结论 / 产出路径 / 验收证据 / **越界声明（无=明确写"无"）** / 环境声明 / **开源替代排查（无自研=明确写"无"）**。

## 7. 铁律 G-OSS-002｜四层落盘

每次沟通 / 回答 / 决策及时提炼落盘：**权威源（`_shared\paradigms\` 或系统偏好）→ 项目 docs → UltimaDocs 镜像（ultima-docs-repo）→ 打 tag**，不拖到之后；寒暄除外。防双源漂移：镜像与权威源不一致时以权威源为准并同步修复。

## 8. 开源替代排查操作定义（怎么写结论）

1. 拆解任务涉及的每个子功能 / 模块；
2. 对每个子功能检索现成开源件（GitHub / 官方文档 / 本机 `libs` 模块库 / 已接入组件）；
3. 逐个判定：可用 / 不可用 + 一句理由（许可、性能、平台、离线、体积等）；
4. 结论写入工单"开源替代排查"字段，格式：`子功能｜现成件｜采用/弃用｜理由`。

## 9. 维护与登记

- 本清单为跨项目硬约束；新增铁律须经用户拍板后由主脑更新并登记（入口：`Ultima-范式存档总纲.md`）。
- 同步链路：本地权威（`_shared\paradigms\`）→ docs 镜像（ultima-docs-repo `docs/shared/`）→ GitHub。
