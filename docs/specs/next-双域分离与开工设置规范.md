## 一、为什么先立规则

旧仓的病根不是代码写错，而是**边界没定**：开发目录与运行目录混用、临时脚本与产品资产混放、测试夹具进了交付、源码被当成运行时依赖。Next 从零重写，第一条规矩就是：**两个域物理隔离，单向流动，任何东西往客户端域加必须先登记**。

---

## 二、双域定义（物理隔离）

| 域 | 位置 | 装什么 | 谁写 | 是否进安装包 |
|---|---|---|---|---|
| **工程域**（Engineering） | `H:\UltimaAI\UltimaAgentNext` | 源码、构建脚本、测试、夹具、打包工程 | 开发者 / Codex | **否**（只有构建产物经打包进入） |
| **客户端域**（Client） | 安装目录（默认 `%LOCALAPPDATA%\UltimaAgent`） | 可执行、运行时、配置、数据、模型、日志、插件槽 | 安装器 / 运行时自身 | **是** |

**单向流动（唯一合法方向）**：

```
工程域  ──构建──▶  dist/（产物）  ──打包──▶  UltimaAgent-Setup.exe  ──安装──▶  客户端域
```

**双向禁止**：

- 禁止**反向**：工程域运行时不得把客户端目录当开发依赖去读取/写入（调试需读写时，用 `devtools` 沙箱副本，用后即弃）；
- 禁止**混入**：工程域源码、测试、脚本、docs、git 元数据**一律不得**出现在客户端域。

## 三、客户端域目录契约（锁定，改动走变更）

```
%LOCALAPPDATA%\UltimaAgent\
├─ UltimaAgent.exe              # 主壳可执行（启动入口，唯一）
├─ HostShell.exe                # 常驻托管壳（如需独立进程）
├─ runtime\                     # Python 运行时与依赖（解包后的 wheel，白名单内）
├─ config\                      # 运行时配置（用户可改）
│   ├─ host-tasks.json
│   ├─ interface-routing.json
│   ├─ voice-profile.json
│   └─ app.json                 # 全局：版本/日志级别/端口
├─ data\                        # 运行时数据（记忆库、任务窗口、状态）
├─ models\                      # KWS / CV3 模型文件
├─ logs\                        # 运行日志（轮转）
├─ plugins\                     # v1.1 插件槽（v1.0 空目录）
└─ version.json                 # 版本号 + 签名信息（单一版本来源）
```

**客户端域禁止项（出现即 Gate 失败）**：

- `.py` 源文件（`runtime\` 内的依赖包除外，且必须在白名单登记）
- `.cs` / `.xaml` / `.sln` / 构建脚本（`build.ps1` / `precheck.ps1` 等）
- 测试用例、夹具、测试数据
- 任何 `docs` 文档、README 之外的说明文件
- `.git` / `.gitignore` / 开发期临时文件

## 五、往客户端域加东西的唯一合法通道：资产登记

**任何新增客户端资产**（文件 / 目录 / 配置项 / 注册表项 / 启动项 / 服务项）必须走登记：

1. 在 `installer\release-assets.json` 登记一条：
   ```json
   { "path": "config/host-tasks.json", "source": "config/host-tasks.template.json",
     "purpose": "Shell 托管任务权威声明", "user_editable": true,
     "uninstall": "keep" }
   ```
2. 打包脚本**只按白名单取**，白名单外一律不进包；
3. `uninstall` 字段决定卸载行为：`delete` / `keep`（用户数据默认 `keep`，资产默认 `delete`）；
4. **未登记资产 = 打包直接失败**（硬门，不是警告）。

同一条规则适用于「往客户端文件夹里加东西」这句话的全部含义：**先登记、后落地**。

## 八、门禁：双域边界必须可机检

`tools\precheck.ps1` 必须包含以下五段，任一失败即 `PRECHECK_RESULT=FAIL`：

1. **构建**：Python 打包 + 原生壳 `dotnet build -c Release`，0 警告 0 错误；
2. **单测**：`pytest` 全绿；
3. **依赖扫描**：终端无关层（Core/Voice/Memory/Middleware/Update）Windows-only 依赖 = 0 处；
4. **双域边界扫描**：工程域内无客户端路径硬编码；客户端域（`dist\client\` 预览树）内无源码/测试/构建脚本/文档；
5. **资产登记校验**：`dist\client\` 内每个文件都能在 `release-assets.json` 找到登记项，未登记项 = FAIL。

## 九、违规处置

| 违规 | 处置 |
|---|---|
| 两个域混用（源码进客户端 / 开发期读客户端） | 任务失败，回退该改动 |
| 未登记资产进客户端域 | 打包失败，阻塞发布 |
| 复制旧仓代码 | diff 审查打回（新文件路径 + 无旧包名 import 双断言） |
| 写入域越界 | 任务失败，重做 |
| 卡片缺设置与功能要求表 | 不派发（DoR 不通过） |

## 十一、三端划分（引擎 / 客户端 / 管理端）——R-49

> 双域（§二）回答"文件放哪"；三端回答"**能力归谁、谁调用谁**"。两者同时成立，不互相替代。

### 11.1 三端是什么

| 端 | 是什么 | 包含什么 | 面向谁 |
|---|---|---|---|
| **引擎（Engine）** | **UltimaAgent 本体** | 八模块：Core / Senses.Voice / Memory / Middleware / Update / Lifecycle / Shell（宿主） / Surface（渲染）中的**能力与数据面**；全部判定、状态机、注册表、记忆、范式、权威源 | 无界面，只提供能力与事件 |
| **客户端（Client）** | 用户看得见摸得着的壳 | 四角壳、HUD 面板、语音交互入口、任务管理器面板、提示与状态灯；**交互策略**（勿扰时段、音量语速、热键、主题） | 使用者 |
| **管理端（Admin，运营）** | 运营/运维视角的后台 | Console 运营面板：任务队列与回执、探针时间线、插件装卸启停、日志查看、审计与冻结记录、自检报告 | 运营者（当前就是你） |

### 11.2 依赖方向（单向，不许回头）

```
管理端 ──只读/受控写──▶ 引擎 API
客户端 ──调用/订阅────▶ 引擎 API
引擎   ──事件/回调────▶ 客户端（呈现）、管理端（观测）
```

- **引擎不依赖任何一端的 UI**：引擎里不得出现窗口、锚位、皮肤、文案排版这类概念；四角壳 8 锚点是**客户端的显示契约**，引擎只发"要显示什么事件"。
- **客户端/管理端不得直接读写引擎的数据文件**（`data\`、记忆库、探针库、权威源）：一律走引擎 API；绕过 API 直读=越界（与 §五 资产登记同级违规）。
- **管理端的写权限是受控的**：装/卸/启停/状态/回执这类操作面可以提交，但**准入校验与生效由引擎执行**（规则面只读，对应 R-26）。

### 11.3 落地口径（当前事实，避免二义）

| 事项 | 定论 |
|---|---|
| UltimaAgent 本体 | **= 引擎**，不包含客户端 UI 与管理端后台 |
| Console | **一件事两面**：引擎侧的**能力**（任务管理/探针/插件协调 = Manager 及其内部子能力）由引擎实现；**管理端**是它的运营 UI 承载。二者是"能力 vs 界面"，不是两个模块 |
| 探针生命周期 | 引擎内 Manager 的子能力（R-28），其**展示**在管理端 |
| 勿扰（DND） | **策略归客户端**（时段、开关、首次开启确认）；**引擎只提供能力接口**（`dnd_state` 状态位 + 静默执行），**不把"23:00–07:00"这类默认时段写进引擎** |
| 媒体 duck | **策略归客户端**（唤醒降到 **20%**、播报结束 **500ms** 恢复、异常退出前强制还原）；引擎只提供"播报开始/结束"事件与 duck 接口 |
| 音量/语速/热键/主题 | 同上，归客户端；引擎只接受运行时参数 |
| 记忆/习惯/范式/权威源 | 全部在引擎，任一端不得直改 |

### 11.4 为什么要这一刀

过去 v1/v2 的"七零八落"，根因之一就是**把显示契约、交互策略、引擎判定混在同一处**：改一个锚位要动引擎，改一个判定要碰 UI。切成三端后：引擎可跨终端复用（Windows→Linux→AR，对应 R-01），客户端可整壳替换，管理端可独立演进。

**禁止**：为了省事把任一端的东西塞进另一端（例：把勿扰时段判定写进语音模块、把锚位计算写进 Core、让管理端直接改记忆库）。命中即越界，按 §九 处置。
